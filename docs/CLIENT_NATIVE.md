# Original client teaching native acceptance plan

Developer-only `DLMS_SMOKE_STAGE=client-teaching` with `--ui-smoke` occupies
23000..23999. It uses the normal original `ccna-gateway` lab and the existing
private synthetic progress directory. It adds no fixture/catalog entry, command,
learner workflow, State/Goal/version or objective credit. This source proposal
has passed its first guarded compilation/checks, but has not run as an actual
native flow. The preceding adapter's70 scoped checks remain a separate accepted
checkpoint.

The fixed plan first starts another real original lab through its library card,
then starts the client through its actual library card. This provides an actual
unrelated saved attempt for selected-reset preservation. The client flow covers:

- Introduction and separate example; Fill changes inputs only; explicit Apply
  and Check establish example outcomes without changing the assignment.
- A measured action menu selects a different actual index, verifies selection,
  and inserts `ip route` without executing. Actual terminal input and Enter/Run
  then inspect the client and test local/remote paths.
- Wrong next hop .130: local .129 still replies while the remote example target
  is unreachable; actual field edits and Apply repair .129.
- Full original task: wrong path, prefix-only partial outcome, native reference,
  pure query preserving truth, raw pending input, atomic malformed Apply and
  retry, followed by the retained disclosed terminal-shortcut alternative.
- Light150 and Dark200 actual focused field typing, Apply, command Enter/Run,
  current error/completion and independent Challenge. Planned images show focused
  fields and terminal/Run separately from the measured feedback block.
- Separate unfinished example/assignment native and terminal drafts, exact saved
  file readback and read-only load, actual library Continue, resumed contexts,
  real Reset Cancel and Confirm, unchanged unrelated attempt and fresh Challenge.

Only fixed trusted source strings become UI events. The driver never calls
engine::execute, directly applies an author action, or publishes a reference
State. Grading assertions inspect actual current state/drafts through existing
pure checks. Save/readback uses the existing writer/private path and the existing16MB-bounded
reader for both exact raw-byte comparisons; reload is
from the exact actual saved profile. Global visited clock may advance on real
Continue, so resume compares state and full workspace rather than inventing an
unchanged visit time. Cancel compares the full selected attempt.

All control clicks use actual measured rectangles and the common visibility
predicate. The menu records `clip_rect ∩ min_rect` after options render, bounds
scrolling to20 attempts inside the actual popup, and verifies the actual selected
index. Completion of a delivered click is handled before consulting metrics that
may disappear after a transition. Text insertion requires the actual clicked
TextEdit to own focus. No guessed row offset or hidden-menu click is permitted.

The plan is bounded to fewer than1000 phases, fields/command literals<=256bytes
and23 planned screenshots. Theme/scale setup uses the existing app-local native
harness pattern. Settle requires actual zoom to equal the requested scale and diagnoses after20
unsettled attempts per phase. It reads Context geometry/zoom/pixels-per-point before any
Context data lock and stores only precomputed scalars. The proposed actual-phase
headless regression calls the real settle stage in a real egui Context; a plan check covers bounded actions, both large-text retries and real resets.
A third real-context test drives the actual phase to its20-attempt diagnostic
for both alternating geometry and stable-but-wrong actual zoom.

practice Enter with a recognized mutating command, retaining exact full-attempt
equality behind Reset/Settings/theme samples. The new client active guard

followup) and four service egui regressions passed on the first guarded attempt.
