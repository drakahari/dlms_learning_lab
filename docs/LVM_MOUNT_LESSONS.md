Navigate **LPIC-2 → Connect LVM filesystems to service directories** after
**Choose which storage LVM inspects**, or search “LVM-backed filesystem mounting.”

- `lpic2-lvm-mount-repair`: diagnose swapped saved and current report/audit
  filesystems, repair automatic policy and distinct rw/ro access, replace the
  live associations, and verify each mountpoint's own original file data.
- `lpic2-lvm-mounted-handover`: rename the same original VG/LV, preserve its
  filesystem/data, and repair the saved mount source using its new canonical
  name or unchanged supplied filesystem UUID. Final mounted state and saved
  policy are assessed independently; continuous zero-downtime history is not
  an assessed requirement and is not inferred from final state.

## Teaching and interactions

columns, saved policy versus current mounts, rw/ro and automatic policy, UUIDs,
canonical names, and real-versus-simulated restrictions. The handover adds the
name-change distinction. Annotated worked actions use separate demo storage.

Try example pairs concise specific instructions with a multiline configuration
editor, explicit Save, actual current-mount rows and the existing simulated
terminal. Command insertion never executes. Fill selected example changes only
the example draft; Save remains explicit. Actual blkid/findmnt/cat output is
computed from supplied inventory, current mount associations and original LVM
file contents. Ungraded examples do not change assignment work or completion.
The experiment unmounts the example while its saved policy remains correct;
repair remounts and rereads the original data before checking.

Assignment has the complete independent requirements and intentionally wrong
or rename-sensitive starter configuration. Solutions are not exposed by default.
Learn/Challenge keep the same substantial task; optional hints and an explicitly
opened worked approach provide assistance. Full objective results remain
available in an expandable section; initial feedback shows a concise failure
summary and first issues. Underlying grading retains every row.

## Checks and persistence

identity/options, original mounted file contents, saved versus draft agreement,
original allocations/files, name requirements and unrelated availability. Saving
alone, an old saved name, a different readable filesystem or the same text from
a wrong original object cannot pass. Valid UUID/canonical forms, option order,
whitespace/comments and supported action orders are accepted. Unmounting or an
invalidating edit/save/name change clears current success.
