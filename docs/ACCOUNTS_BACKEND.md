## Publication requires the authored context

`State::Accounts { simulation }` contains the current bounded account state only. `Goal::Accounts { initial, requirements }` retains one immutable authored initial state; it is not duplicated into every engine state or rewritten as history. Pack validation requires that goal initial equal the scenario's initial simulation exactly, with validated typed outcomes and required separate teaching. Goal/outcome collection decoding is capped at64 before another owned requirement is accepted.

`engine::execute_for_goal(state, goal, input)` is the assignment boundary. For Accounts it validates requirements/current context, executes through `accounts_teaching::execute_in_context` and publishes only a candidate that passes `valid_against(immutable_initial)`. The helper checks current context before cloning. A command that intrinsically deletes/recreates an authored name with a different UID can never publish that incompatible state. Errors retain the exact previous account simulation. Queries and help do not mutate. Raw `engine::execute` permits Account queries/help but honestly rejects mutation without the goal context.

All other state kinds delegate to their original `execute` path unchanged. Pack solution reachability and the existing native assignment submit call both use the new wrapper, so an author's accepted sequence and a future learner's account commands share the same context gate. This change does not add an account renderer or claim a completed learner flow. Launch/reset only prepare optional account practice metadata when a private account scenario is supplied. No ACL goal members or dispatch were changed.

Account `checks` are fresh typed current-state checks, including immutable context and whole expected configuration where authored. The private fixture creates a requested group, repairs supplementary and primary membership, observes primary-GID home effects and preserves every other record/file. Different valid command orders, duplicate-free final sets and extra investigation queries pass; readonly/partial/wrong-peer/damaged-evidence states fail. There is no event/call-count/string-to-success requirement. Meaningful account-expiry metadata remains separate from authentication, password locking, PAM and actual login. No host account tools or learner subprocesses run.

## Teaching and separate editable practice

`Scenario.accounts_teaching: Option<Lesson>` and `WorkspaceData.accounts_learning: Option<Learning>` are optional serde fields omitted when absent. Old scenario/attempt encodings therefore gain no invented answers, completion or account metadata. Account activities require their teaching; unrelated activities reject attached account teaching/goals.

`accounts_teaching::Lesson` contains prerequisite prose, concepts, default example commands, one matching annotation per command, input explanation, a different fixture/date/identities, typed outcomes, one concrete try-change with runnable actions/outcomes and a repair sequence. Validation runs the default/change/repair in the same fixed-context helper and checks declared current outcomes. It rejects empty/oversized teaching, undocumented commands, initially-solved examples, unsupported/unreachable examples, unchanged experiments and ineffective repairs. These validation executions are author checks, never automatic learner actions.

The authored initial example's nonroot usernames/UIDs and group names/GIDs are disjoint from the assignment's initial records, the fixture key/date differ, and all files belong to its separate in-memory simulation. Root0 may be shared because it is protected context, not a target. Later coincident record creation in the independent simulations remains valid. `Learning` stores version/view/current simulation/selected example index/command draft/transcript/checked flag, with no immutable full fixture duplicate. Its methods always receive the original Lesson:

- `new(lesson)` starts Introduction with the independent initial example simulation, empty command/transcript and no assignment credit.
- `fill_example(lesson)` changes only the selected command-input string. It does not execute, alter the simulation, clear existing transcript/check flags or advance commands.
- `execute(lesson)` requires `valid_for(lesson)`, consumes one nonempty bounded command and executes with `lesson.fixture` as immutable context. Ordinary parse/command errors retain simulated data and append bounded feedback; a corrupt/mismatched practice context retains input/data and is refused. No assignment mutation or success follows.
- `checks(lesson)` recomputes against the current example simulation on every call. There is no cached passing result. The checked flag is display intent only, never authenticated credit.
- `prepare(attempt, lesson, new_attempt)` creates metadata only when absent, preserving valid unsaved drafts. Existing attempts initially show Assignment; new attempts start Introduction. Reset must replace only the selected Attempt from its authored scenario and independently prepare its example.

Default private example identities are Tess/Omar/sample-keeper and sample groups, with a supplied March date. Assignment identities are Mira/Bryn/archive-daemon and a different October date. The example teaches append versus replacement and primary-group home changes before its experiment; the assignment's names, IDs, files and date never leak into or execute inside that example.

## Saved state, bounds and recovery limits

Command drafts permit incomplete literal quotes (maximum2048 bytes) because unsaved input is not executable state. Save/load preserves that draft exactly; executing it later reports an honest parse error without changing the simulation. Practice transcript bounds:40 rows,36,000 bytes/row and131,072 bytes aggregate, with string/count/aggregate visitors and oldest-row trimming. Root/library query output and512-byte fresh account diagnostics retain the accepted pure-core bounds. No transcript is a completion credential.

`progress::decode` pins account assignment simulations against the scenario's immutable initial state and practice simulations against its original Lesson fixture, including policy/protected data/identity pins and command selection. Wrong-kind account metadata, identical assignment/example fixture/date markers, invalid practice shapes and corrupt indices are rejected. Namespace disjointness applies only to the authored initial fixtures: a learner may later create a name/UID/GID coincident with the other independent workspace, and that state remains saveable/loadable when each simulation satisfies its own immutable context. `current_solved` also requires matching account goal/scenario initial context and valid current simulation before normal engine checks. Current edits can invalidate current success; an old pass is never a substitute.

Generic `progress::save` has no authored catalog parameter, as before. Its save-side guard rejects malformed/wrong-activity metadata and identical immutable assignment/practice fixture/date markers before any write; it does not compare evolving current record namespaces. It does not pretend to authenticate an arbitrary example fixture against unknown authoring data. Authored pinning belongs to decode and the fixed-context execution/publication boundary; future UI callers must preserve those gates. Tests exercise exact file-byte retention on wrong-kind save rejection, decode-side corruption/cross-fixture rejection, and both directions of legitimate new group/user/name/UID/GID overlap followed by exact save/load. No new schema version, shell migration receipt or legacy relabeling is needed solely for optional account metadata.
