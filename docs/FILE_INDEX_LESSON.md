New stable lesson `lpic1-file-index-handover` belongs to **Saved filename searches
and private indexes**, after live-file search and Linux application-file locations.
It addresses a narrow part of LPIC-1 5.0 objective104.7. It does not close the whole
objective or cover global locate visibility, whereis, timers or arbitrary flags.

The assignment combines three related repairs: diagnose a genuinely stale saved
name list, correct an accidentally excluded current branch, explicitly rebuild a
private index and hand over the current document. A matching filename alone does
not prove that the copied contents are current. Saved exclusions, actual index
freshness, the full handover file and preservation are graded independently.

The Introduction teaches live versus saved-name search, PRUNEPATHS, explicit
refresh, locate -e and checking contents, with a separate gallery worked example.
Try example uses a real native configuration editor and simulated terminal. It
compares find/locate, saves configuration, rebuilds, copies, then removes/restores
a declared practice file to observe stale and existence-filtered results.
Assignment retains the full practical task with requested hints and optional
worked help; Challenge hides unsolicited guidance, retaining the same task.

## Implementation and authoring

- `file_index` contains bounded typed name snapshots, literal command parsing,
  semantic pruning and explicit rebuild/query behavior.
- `file_index_workspace` keeps separate assignment/example Current values and
  drafts. Session never stores the expected Definition or reference answers.
- `file_index_source` pairs every action, grade, save and resume with the actual
  held catalog definition. Wrong activity families and erased snapshots refuse.
- The native page reuses bounded editor/input and aligned control components.
  Config Save never rebuilds. Pending edits invalidate success without silently
  applying configuration; failed actions retain the pre-entered text for retry.
- Scenario packs supply distinct role IDs, initial stale snapshots, ordinary
  trees, expected outcomes and typed author-only Save/command references.
  Constructors/render/load/reset never execute a reference. Pack admission
  explicitly checks reachability and the worked/exploration repair sequence.

Config whitespace, duplicate/redundant exclusions and supported copy paths may
vary. Grading uses the actual resulting state, not exact commands, history,
walkthrough position or a generation counter. It does not prove which search
commands the learner used. A wrong archive copy, stale-only repair, broad index
or altered required permissions fails even if another part is correct.

The private index is an opaque typed artifact shown by name/count. It is not
fake plocate binary bytes in the ordinary tree. Unsupported generic database or
storage-folder operations explain that boundary; the data-root find/cat/copy
commands still operate on real simulated state. No host command or file access
is reachable from learner input.
