# Local device access: named accounts and a safe handover

Development milestone, 2026-11-09. This unit follows **Remote management:
protocols and approved sources** in CCNA. It addresses a bounded practical part
of objective 5.3; remote AAA, cryptography and complete objective coverage remain
outside the implementation. See [the model contract](LOCAL_ACCESS_SUBSET.md).

## Two distinct assignments

| Stable ID | Independent work | What the investigation teaches |
| --- | --- | --- |
| `ccna-local-account-setup` | Configure the two supplied local accounts with different access levels, explicit case-sensitive login and local EXEC authorization. Retain all incoming-access requirements. | An allowed workstation is different from an authenticated identity; a valid credential is different from the correct access level. |
| `ccna-local-account-handover` | Establish the new maintainer, keep the observer restricted, and remove the former maintainer without weakening incoming policy. | Rotating or renaming an unwanted account does not retire it. Individual successful trials do not establish that the permitted account inventory is correct. |

The Introduction teaches authentication, authorization, the supplied method and
levels 1/15 before showing a worked configuration with different sample values.
Try example retains its own editable document and contextual actions. Apply policy
validates and atomically applies the complete document; Inspect trial reports an
actual virtual path/policy/local-record decision. Check configuration evaluates
the complete source-held requirements. Filling a worked example does not execute
or award assignment credit. Challenge retains the same independent assignment.

The assignment provides the required training words and names but no completed
configuration by default. These are lesson data saved as text, not personal
credentials. No SSH server, shell, hash generator, host account or network is used.
The editor deliberately accepts a disclosed complete-document subset rather than
pretending to implement an incremental IOS terminal.

## Grading and saved work

Each assignment checks the exact permitted account set, six incoming-policy cases
and six account cases across all sixteen supplied VTY lines. A malformed document
is a diagnostic, not a negative-case success. An upstream path or source-policy
block cannot satisfy a required local-credential rejection. Correct credentials
with excessive privileges fail. Wrong words, unknown names, differently cased
names and surplus records are checked independently.

Equivalent supported record ordering, line grouping and source-rule decomposition
pass. Edits invalidate current success and trial observations. Bounded drafts,
applied documents, selectors and separate practice/assignment work survive safe
save/restore; reports are recomputed against the bundled source. Transient trial
output is not imported as newly executed evidence. Reset affects only the chosen
attempt. Existing IDs, scenario/unit objects and prior progress are preserved.
