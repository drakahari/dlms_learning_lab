# Virtual filesystem subset (capability work)

Specified 2026-10-22 before dependent lessons. This is a typed, in-memory Unix tree, separate from the application's own storage. No learner path is passed to a host file API. It runs as one ordinary simulated user; no sudo, root override, host processes or network.

Initial command scope: pwd, cd (including home/previous), ls (-a/-l/-d), cat, mkdir, touch, cp/mv of ordinary files, rm (-f) of ordinary files, rmdir of empty directories, and numeric umask. One operand per file-creation/removal command and two for cp/mv. Option terminator -- and literal single/double quoting are supported. Shell expansion, pipelines/redirection, recursive operations, links, devices, ACL/SELinux, special mode bits and arbitrary command execution are unsupported and diagnosed. The older permission/log/service models retain their own disclosed subsets.

Paths are resolved component by component inside the virtual root, including search permission before '..'; normalization cannot skip an inaccessible or missing directory. Directory read vs search, file read/write, parent write/search for creating/removing/renaming, new-file umask and cp-vs-mv metadata behavior are modeled. No sticky-bit, mount or hard-link model is implied. Runtime command failures retain the prior state; the supported single-file operations validate before mutation.

Files are UTF-8 text without NUL; path components exclude control characters and are bounded. Timestamps use a deterministic simulated epoch, not the learner's clock. Maximum 256 entries, 128 KiB in one file, 256 KiB total file data, 1,024-byte paths, 64 path components, 32 KiB command output and a bounded simulated clock. These are educational limits rather than kernel behavior. Every command operates on a bounded cloned candidate and commits only a valid resulting state.

References checked for authoring: [LPI 103.1/103.3 current objectives](https://www.lpi.org/our-certifications/exam-101-102-objectives/), [GNU coreutils manual](https://www.gnu.org/software/coreutils/manual/coreutils.html), [POSIX path resolution](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html). Direct GNU page retrieval timed out in this check; use installed GNU manuals and controlled development fixtures for detailed command comparisons. Capability validation: eleven Rust filesystem tests and 79 controlled GNU command comparisons. This capability is not implemented curriculum coverage until authored lessons are delivered.

Absolute paths always start at the **virtual** root. Relative paths start at the already-open working directory; target permissions do not incorrectly recheck unreachable ancestors. `rm -f` suppresses missing/non-directory component errors, while search-permission failures still fail. Bare `cat -` (terminal input) and `touch -` (output descriptor) are explicitly unsupported, even after `--`; `./-` names a literal file. Removing the current/home directory is unsupported; a deleted previous-directory path remains remembered and `cd -` reports it missing.

`ls` uses C-style name ordering and one entry per line. Long listings show modeled permissions, link counts, owners/groups, text byte lengths and deterministic timestamps. Directory byte sizes are zero, block totals and SELinux/ACL suffixes are omitted; these are not claims of a complete GNU listing. Controlled reference comparisons check supported fields, not these disclosed differences.
