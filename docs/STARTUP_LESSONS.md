## Grading and preservation

The unchanged unit_manager core parses bounded service/target definitions and
builds actual dependency/install graphs over fixed supplied virtual programs.
Each task grades current runtime, actual consumed inputs, required install links,
selected target and preserved documents/configuration/other links. A separate
copy starts the selected next target and checks required running/absent services;
that check cannot repair current work. Program ports are values only.

Start/Stop and Enable/Disable remain independent. Enable reads saved installation
metadata and also reloads definitions in this disclosed model; an explicit
Daemon-reload remains useful to teach the separate saved/loaded stage. Editing
WantedBy does not move old links. Set-default does not isolate/switch the current
session. Supported alternative command orders are accepted; editable text is
parsed by meaning, rather than exact solution strings. Pending editor work and
later policy damage invalidate current success even when prior checks passed.

No new engine, progress schema, dependency or shell behavior was added. Prior235
lab and63 unit objects have a separate exact historical snapshot; comparison API
names do not mean the owner accepted new content. New lesson IDs are stable.
Private review profiles are separate from installed/original progress.
