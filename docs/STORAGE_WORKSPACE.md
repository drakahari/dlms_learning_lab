## Grading and feedback

Typed `PersistentMounts` goals pin the authored inventory. Every fixed mountpoint needs explicit saved and live outcomes; at least one current mount and one changed-alias fresh test are required. Each fresh expected table covers every mountpoint and includes a positive mount. Identity baseline tests are also permitted. Grading compares resulting volume identity, effective policy, supplied dump/check metadata and live state, not command spelling or exact configuration text. Comments, supported option orderings and legitimate action orders remain alternatives.

Fresh checks revalidate saved configuration and every saved identity/policy under **each test copy's inventory**, including `noauto` rows. Merely skipping a wrong manual source cannot pass. Goal maps reject duplicate keys before validation. Examples/reference solutions must reach all outcomes; a declared practice change must execute in memory and actually change state. Configuration root causes are displayed once before dependent failures, while the full outcome list still determines completion. Pending editor changes, broken saved configuration, wrong/removed mounts or changed identity clear current success.

Test saved mounts reports actual clone volume IDs/UUIDs and manual-source resolution, without changing the learner's current session. It does not infer business purpose from an inventory command or claim a system boot. The native terminal accepts only documented literal `blkid`, `cat /etc/fstab`, `mount` and `umount` forms. Unsupported syntax is diagnosed. JSON reachability actions belong to authoring data; they are not accepted as learner terminal commands. There is no shell, host device, file, service or process access from these operations.
