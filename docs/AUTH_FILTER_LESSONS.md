## Workspace and outcomes

A native multiline editor saves only the declared virtual filter. The read-only
log table distinguishes Unchecked, Matched, Ignored and Missed. Choosing another
sample marks its rows unchecked until a test runs. Editing leaves the prior saved
file/test distinct from the unfinished draft. Saving changed text invalidates the
old test and current check; unsaved changed text also prevents current completion.

The virtual command bar supports `cat FILE` and the disclosed numeric-only
`fail2ban-regex` file/filter form, plus explicit result-printing flags. It never
opens a host path or starts a daemon/firewall. Actual console counts and line rows
come from the parsed saved filter. Unsupported syntax/options/paths give a real
limitation diagnostic. A refused read-only query does not damage an otherwise
correct saved configuration. A syntax/unsupported-definition error blocks the
sample checks rather than presenting a misleading passed-case total.

Grading evaluates contrasting deterministic cases with fresh actual observations,
not a regex string or a command-success flag. Equivalent supported patterns pass;
first-case literals, broad event rules, ignore-everything and identity-only
exceptions fail. Feedback identifies the affected sample/line, expected versus
actual category and the likely misconception without supplying the graded regex.
