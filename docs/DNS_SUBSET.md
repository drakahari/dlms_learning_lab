# Authoritative DNS capability contract (M38)

Specified2026-10-23 before implementation. Add a bounded pure DNS model before dependent curriculum. Retain the original nine scenarios and their progress; the earlier single-A-record exercise is a separate compatibility model. This capability alone adds no authored lab or objective coverage. Native integration and reviewed content follow in separate milestones using the accepted editors and shared layout controls.

Model one configured primary zone, the currently loaded primary copy and a secondary copy, with typed A, AAAA, CNAME, MX and NS records. Query only in-memory copies. Owners and targets use bounded ASCII domain labels, case-insensitive comparisons and fully qualified names; trailing dot is optional and never implies a relative name. No wildcards, IDNA/escaped labels, arbitrary zone-file grammar, recursion, delegation/glue, caching/expiry timers, actual packets/services, DNSSEC, TSIG or host I/O. Return honest unsupported/invalid/configuration diagnostics rather than fabricated network success. SOA serial/origin are modeled metadata; other SOA fields/query types remain explicitly unsupported.

Distinguish successful answers, an existing name with no requested type, nonexistent names, out-of-zone queries and bounded alias failure. CNAMEs cannot coexist with other ordinary data or have multiple different targets. Follow only the supported in-zone alias chain, with visited-name/depth bounds; an external target returns its authoritative CNAME evidence without pretending to resolve externally. Case-insensitive duplicates form one RRset, equal-priority MX alternatives remain valid, and query output is deterministic rather than a claimed delivery order. Uniform returned RRset TTL uses the smallest supplied TTL. MX/NS targets must be canonical, not CNAME aliases.

Primary reload validates and atomically replaces the loaded copy; it must not invent a rule that a primary cannot load changes with an equal serial. A separate explicit simulated secondary update uses32-bit serial arithmetic: newer values transfer, equal/older retain the copy, and exactly half-range comparisons are undefined and diagnosed. Distinguish configured versus served state and manual update behavior from a real transfer protocol/refresh timer. Preserve previous loaded state on any invalid reload.

Configuration checks validate supported structure, zone ownership and known alias conflicts; they are not an emulation of BIND's named-checkzone or a declaration that DNS/mail service is operational. A separate target_readiness check reports NS/MX hosts with an in-zone A/AAAA record, missing in-zone address records, or unknown external addresses. The last case must never be described as resolved without recursion. Operational assignments must explicitly require relevant address/lookup evidence. No SMTP delivery or server reachability is modeled. The original single-A-record seed's increasing-serial reload rule is an exercise constraint, not a universal rule for real primary reloads; the new model deliberately separates primary publication from secondary serial decisions.

The answer's authoritative flag describes authority for the original in-zone question, including alias failures. It is not a success flag. Callers must examine the response code and requested-type records; an authoritative SERVFAIL or NXDOMAIN does not mean the requested host resolved. Alias failures return no successful answer records. This is a data/diagnostic model, not a complete DNS wire-message implementation: authority/additional sections and negative-cache SOA records are omitted.

Bounds:64 records per zone, domain wire length255/label length63, unsigned32-bit serial and TTL range0..2^31−1,16 alias links and bounded validation/query work. Loaded copies must be valid; configured copies may carry bounded semantic mistakes for repair. Future import adapters must pin supplied zone identity and physical/server shape; never let changing the task inputs earn credit. Future goals need full current configuration, served answers on intended copies, preservation requirements and deterministic alternate/negative cases.

Verify A/AAAA RRsets, case/trailing dots, CNAME chains/loops/conflicts, empty nonterminals/NXDOMAIN versus no-data, MX priorities, canonical targets, atomic reload, equal/newer/older/wrap/half-range serials, stale secondary behavior, order/duplicate alternatives, malformed names, maximum bounds and no host I/O. Use authoritative standards as behavioral references; no network queries or real server changes. No dependency or major application architecture change.

Primary references checked2026-10-23: [RFC1034](https://datatracker.ietf.org/doc/html/rfc1034) sections3.6.2/4.3.2; [RFC1035](https://datatracker.ietf.org/doc/html/rfc1035) names and RR formats; [RFC2181](https://datatracker.ietf.org/doc/html/rfc2181) RRsets/TTL/canonical targets; [RFC1982](https://datatracker.ietf.org/doc/html/rfc1982) serial comparison. LPIC-2 v4.5 objective207.2 and CCNA v1.1 DNS service explanation are future narrow mapping targets, not completed objectives. Full recursive DNS, transfers and security requirements remain Open.
