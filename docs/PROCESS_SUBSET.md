# Process inspection, signals and niceness: bounded capability contract

Specified2026-10-23 before dependent content. **Capability and native/persistence integration implemented and tested; authored process curriculum not yet bundled.** This models a fixed table of at most64 virtual Linux processes, effective identities and sessions; no actual process is listed, spawned, signaled, reniced or observed by learner input. No new dependency is needed. The simulator remains in process and offline. This capability alone will not promote an objective or add a lab.

Processes have positive stable PIDs, parent IDs, owner identities, session IDs, executable names, integer nice values and typed running/sleeping/stopped/exited phases. PID1 is a protected synthetic init. Executable names are up to15 ASCII bytes, limited to letters/digits/underscore/dot/hyphen with no leading hyphen. Exited entries stay in bounded internal history but disappear from ps/pgrep; children of an exited parent report parent1. There is no PID reuse, zombie/wait model, thread table, actual CPU time, scheduler performance, supervisor respawn or interactive shell job control.

Initial command subset:

- `ps -eo COLUMNS` or `ps -e -o COLUMNS`; `ps -p PID[,PID...] -o COLUMNS`. Explicit format required. Columns: pid,ppid,user,stat,ni,comm, in requested order. Header/value formatting resembles procps, with R/S/T states and visible nice values; it does not invent host CPU/time/TTY data. Combined selectors, custom headers/widths, sorting, threads, other formats/default selection remain unsupported.
- `pgrep -x NAME`, optionally `-u USER` (a modeled username only), in either option order. Patterns limited to letters/digits/underscores/hyphens, where -x full-name regex matching equals literal matching; metacharacters (including dot) are explicitly rejected. Arbitrary regex, full command lines and other flags unsupported. No matches returns1, without inventing an error.
- `kill [-s SIGNAL|-SIGNAL] [--] PID...`; default TERM. Positive PIDs only; process groups, PID0/-1, queued values and arbitrary signals unsupported. Supported Linux x86_64 numbers/names:0(permission check),2/INT,9/KILL,15/TERM,18/CONT,19/STOP. Prefer names in teaching. SIGINT/TERM have default termination disposition; SIGSTOP cannot be ignored; SIGCONT resumes a stopped process to its prior activity. INT/TERM sent to a stopped process remain pending until CONT; KILL exits immediately. Multiple standard terminating signals coalesce because no handler/exit-status distinction is exposed. Handlers, blocked masks and arbitrary scheduling are excluded.
- `renice [--priority] VALUE [-p] PID...`: absolute nice value -20…19. Ordinary users can only raise their own nice value (lower urgency), with RLIMIT_NICE fixed0; root may change any modeled process. `-n`, relative/group/user modes and nice/spawning are initially unsupported, avoiding environment-dependent -n behavior.

Signal permission uses the modeled effective identity, plus the Linux same-session SIGCONT exception. Real/saved IDs and capabilities are collapsed/excluded and must be disclosed. PID1 is protected from mutation even for root in this subset; signal0 can still check ordinary permission. A successful signal or renice returns current computed outcomes; no success depends on matching a lesson string. Runtime errors for missing/unauthorized targets report failure while other valid targets in the same command can still change. Unsupported or malformed forms fail before any mutation. Command length4096bytes/128words, bounded integer parsing, fixed table and bounded output prevent unbounded work; no waits, loops or external calls occur.
