## Deliberately narrow supported forms

```text
host -t A NAME. SERVER
host -4 -t A NAME. SERVER
```

SERVER is one of the existing source-supplied numeric IPv4 resolvers. NAME. is an
absolute supplied .lab.test name. -t A asks for an IPv4 record; optional -4 selects
IPv4 server transport, a separate concept from record type. Only known positive
A records are described in these snapshots. Default multi-type/reverse lookups,
implicit or named servers, other flags/types, missing-data/existence responses,
search, recursion, TTL, caches and real transport remain unsupported. An omitted
record never becomes an invented NXDOMAIN/NODATA answer. Unknown input fails
without changing the world. Neither utility executes on the learner's computer.

The adapter shares the same actual record lookup and current virtual IP-path
check as dig. Typed observations carry a transient utility choice, not saved
answers. host prints the selected-server banner and a has address line, then a
separate simulator note. #53 in the banner is the supported utility's default
service-port notation, not an observed socket/packet. Positive status0 means an
answer was supplied; it does not prove that the client uses it or meets the task.
Unavailable virtual paths are labeled model observations with no invented timeout
or utility status. Existing512-byte/source-record/history bounds remain.
