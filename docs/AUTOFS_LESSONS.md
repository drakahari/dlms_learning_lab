map, directory/key composition, direct full paths, the leading option dash,

active versus mounted state, and settled simulated expiry before assessment.

## Scope and authoring

See [closed model and primary references](AUTOFS_SUBSET.md). The simulator reuses
original virtual LVM filesystem identity/data and the existing pure ext4 mount
engine. It has no host calls, real AutoFS daemon or network map. Supported terminal
commands are only supplied `cat` paths, `findmnt -t ext4 [supplied point]`, and
`systemctl reload autofs` for the supplied already-running simulated automounter.
Native idle checks are simulator controls, never taught as Linux commands.

`src/autofs/maps.rs` parses the closed local-file subset; `runtime.rs` owns saved/
loaded maps, demand mounts and per-point idle records. `autofs_workspace.rs`
validates source-held tasks, separate drafts, typed operations/replay and current
behavioral grades. `autofs_source.rs` binds packs and saved work to their caller's
catalog. `src/ui/autofs_page.rs` uses the approved native teaching/control helpers.
No other track receives a new appearance or engine. There are no new dependencies.

New data lives in `scenarios/autofs-{lessons,units}-v1.json`, with two appended
LPIC-2presentation rows. Every typed teaching operation has an explanation and
expected status. The loader proves the reference reaches outcomes, the practice
change breaks an assessed condition, and the retry repairs it. Reference action
labels must match the typed operations; a Save description is not a shell packet.
Activity/world/config/history/output/clock limits are enforced independently.
