# PTR native acceptance controller

Source proposal, 2026-10-25. No new native run or test result is claimed here.
The controller requires the three normal `dns-reverse` scenario IDs to be
registered. It neither appends a private fixture nor changes the catalog.
The source worktree still has the earlier normal catalog; normal registration
is a separate reviewed integration prerequisite for its plan/Finish tests.

`DLMS_SMOKE_STAGE=dns-reverse` selects the private 27000–27999 acceptance range.
Normal startup and the existing forward-DNS and seed-teaching controllers keep
their existing paths. This is a fixed development controller, not learner
command execution or novice acceptance.

The controller parses the independently reviewed scenario authoring data only
to obtain desired resource-record text and serial values. It types those values
through the actual record/serial editors and clicks Save zone, Reload primary,
Update secondary and Check. It never executes an authoring action, installs a
solved State or treats lookup output as grading authority. An alternate reverses
record order, changes TTLs and raises the serial; the handover alternate leaves
an unrelated A record at the retired PTR owner to demonstrate valid NODATA.

For each lesson it opens the real library card, captures the Introduction, and
uses the separate example. Fill must change only the example draft. Actual
publication and Check are followed by the lesson's independent experiment and
repair. The assignment then exercises initial wrong results, saved-only partial
results, explicit publication, all current requirements and a valid alternate.
The handover checks both served copies and the retired name. Real query fields
and bounded, clipped popup selection exercise PTR and Secondary lookups without
changing current credit.

A malformed serial is typed after completion. A rejected Save must retain both
the invalid draft and the exact applied State; Check then shows pending work.
Actual typing and publication repair it. Challenge hides assistance. Distinct
unfinished example and assignment drafts are saved, bounded-read back, reopened
through the library and compared exactly. Reset Cancel retains the selected
attempt; Confirm resets it while other attempts and favorites remain unchanged.
The task is completed again through the controls.

The IPv6 task types and repairs at Light 150%; the handover types and repairs at
Dark 200%, with an additional actual full-screen Light 150% task view. Measured
zoom and wide/windowed viewport predicates must settle within 30 attempts.
These are app-local presentation changes. They make no compositor, platform,
Wayland-startup or accessibility acceptance claim.

Passive metrics retain actual response IDs/rectangles for the fields, type/copy
pickers, popup content, notices and first current feedback label. Multiline
editor focus uses a font-derived band inside its viewport, not an impossible
whole-content reveal. Feedback captures reveal the measured current label;
lookup captures reveal the actual output viewport. The shared bounded reveal
and popup-scroll helpers retain their clipping and click-completion guards.
No drawing, widget order, grading, IDs or input behavior is changed by metrics.

Finish checks all three current goals before announcing success and repeatedly
requests asynchronous Close without advancing out of the stage. Profiles,
images, logs and measurements remain private runner-owned artifacts.

Five proposed checks cover the normal fixed plan and scale-specific typing,
actual geometry-phase Context access, click completion after metrics disappear,
Finish rejection/Close retention, and real editor typing with a rejected Save.
All are unrun at this source checkpoint. The first guarded gate must follow
normal registration and use the MAIN runner's exclusive worktree target, then
all-target Clippy, formatting and an identified build. Actual native acceptance
requires a separate root-owned grant and render review.
