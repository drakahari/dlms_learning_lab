# Counters, totals and safe publication

Authored2026-10-22 after bounded arithmetic/reference validation. Four distinct assignments use portable shell syntax within the disclosed subset. They follow the stream/input and reusable-interface foundations. No new dependency or host execution is involved.

| Assignment | Practical reasoning | Deterministic cases |
| --- | --- | --- |
| Number a handover queue | Keep one counter across input records; preserve blank/final records and literal text |6: ordinary, blank rows, unterminated final record with a different spaced filename, punctuation/backslashes/internal spaces, empty, only blank rows |
| Calculate an order total | Accumulate quantities, multiply a whole-cent rate, distinguish calculation from concatenation |6: ordinary, zero/final record, empty, zero rate, one quantity,64 quantities of999 at rate99 |
| Plan full cartons and leftovers | Integer quotient/remainder, argument guard and intentional zero-capacity rejection |8: remainder, exact fit, less than one group, no items, capacity1, capacity0, missing and extra arguments |
| Publish a trustworthy count report | Preflight all sources, reset per-file counters, retain grand total and publish without damaging input |8: old report replaced, repeated source/blank/final records,8 sources including spaced/empty/16-record files, later missing source/retained output, missing/new output, output/input collision, no sources, empty destination |

Learn teaches the new ideas before assessment, with separate persisted examples and exact experiments: advance by two; change arithmetic grouping; try a zero divisor behind a guard; count files rather than records. The first example introduces the single `done < file` form using its own stop list. Challenge retains the same complete assignment/editor without unsolicited teaching or solutions. All example Runs use the bounded VM and cannot earn assignment credit.

Reference methods, supported alternatives, plausible incorrect/partial programs, hardcoded first-case results/paths, early file creation and stale success are tested. The capstone also exercises the declared maximum8×16 records, with different filenames. Existing IDs/versions, earlier results and independently persisted assignment/example drafts remain intact. Reset changes only the selected attempt. No new evaluator revision is required: the added while-input form was previously rejected, and nonredirected loops retain their instruction count.

Scope is deliberately explicit: small nonnegative integers with canonical decimal notation and no leading zeros; supplied quantity/price values need no lexical validation. General numeric validation is **not** covered. Whole cents are integers, not decimal money arithmetic. Input records have no edge spaces/tabs because default read trims those; internal spaces remain literal. Arithmetic commands, floats, arbitrary precision, command substitution and general compound redirection remain unsupported. Only one trailing `<` on a while loop is accepted. Active source snapshots are read-only: truncate/append/write fails explicitly before mutation. This is not live changing-file behavior. Canonical single filenames make textual equality sufficient for these supplied data, not real filesystem alias safety.

Primary references: GNU Bash arithmetic-expansion/Shell Arithmetic sections and POSIX Issue8 shell grammar, linked in every scenario.
