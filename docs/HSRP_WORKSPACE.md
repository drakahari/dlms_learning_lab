This unregistered source proposal extends the reviewed pure HSRP foundation.
It adds no authored pack, unit, normal catalog entry or coverage credit. CCNA3.5
remains Open. The supplied Rust scenario is a synthetic test fixture only.

separate gate; source review and formatting establish no runtime acceptance.

The three new implementation modules contain the learner session/source boundary,

## Meaningful configuration and current outcomes

Exactly two supplied routers and1–8 clients share one connected IPv4 LAN and a
fixed HSRPv1 group/VIP. Learners edit participation, integer priority, preemption,
one optional WAN-link tracking decrement and permitted client gateways through
aligned native controls. Incomplete or invalid drafts can be retained but cannot
be applied or display completion. An Apply stages every changed field before
publishing; a failure preserves all prior applied state and draft. Identical
settings consume no configuration-history entry.

Both routers must participate. Every supplied client must use the VIP and have
modeled forwarding in the current state. Every checkpoint of every authored
failure/return sequence is then checked on a clone of that configured state,
including every client and an optional required Active identity. Each policy
must cover failure of both routers; a final healthy checkpoint cannot hide a
failed intermediate step. A real-router gateway can appear healthy before
failure and still fails the VIP/resilience requirement. Disabling the other
candidate cannot be used to earn success. Priorities and preemption are accepted
according to behavior, rather than a single canned configuration string.

Author-owned grade probes support power, LAN-link and WAN-link events. WAN loss
does not magically remove the Active: effective priority and a strictly
higher-priority preempting peer must cause the required takeover. Link tracking
is not route tracking. Route/client-link faults and unsupported peer partitions
can also be examined through the separate inspection API, with the pure core's
honest diagnostics/refusal; they are not invented automatic routing mechanisms.
The initial task facts are healthy and fixed in this focused capability. Fault
repair of an initially powered-off router is outside its current scope.

The native default shows equal shared topology cards and their centered
connector, readable Active/Standby/effective priorities, router fields, client
gateways, Apply/Check and concise outcome feedback. Detailed checks and temporary
inspection are optional. Failed rows say Needs attention, not just a red positive
assertion. Temporary observations are labeled separately from configured work.
The native form has no IOS terminal and makes no packet, ping, real convergence,
ARP, host-network or wall-clock claim. All events are already settled.

## Incumbency and authority

The persistent assignment cannot edit power, LAN/WAN, route or client-link facts.
Core `environment_matches` checks identities but intentionally permits faults;
this workspace additionally compares every fixed fact. Protected configurations
and gateways are enforced by the source's explicit editable identities.

A session stores the exact settled current state and up to128 actual ordered
configuration changes from the source initial state. Admission replays those
bounded typed changes through the pure core and compares the entire result,
including incumbent/standby and revision. Valid lower-priority incumbency is
retained; resume never sorts priorities again. A forged settled role or revision
without its permitted history is refused. An unchanged/no-op history record is
also refused because it was never published by this workspace. At the limit,
new changes refuse atomically; selected Reset starts a fresh attempt. No history
is silently pruned or rebased onto a self-carried checkpoint.

Initial markers, current facts and history cannot supply source authority by
agreeing with one another. State and initial markers bind to the app-owned
Scenario/Goal. Saved progress contains no accepted catalog or Goal override.
Source-aware normal Save checks every new HSRP attempt, including nonselected,
missing-source, wrong-kind, foreign-source and forged-marker cases before the
unchanged existing writer. LVM and NTP validation remain independent branches.
Save performs no grade probes, reference solution or pack reload: it validates
source/model/history structure and replays only bounded configuration changes.
Load, export, backup inspection, restore and completion use the same owned-source
boundary. Source parameters themselves must come from the app's validated catalog;
this is not a digital signature or authentication of an arbitrary caller's Goal.

Temporary inspections clone applied configuration and accept at most eight
explicit events. They never overwrite persistent models/history, publish a grade
or stamp progress. Source-owned assessment probes do not consume or trust the
inspector's selected fault facts. Reset/return changes in a temporary observation
cannot forge the persistent incumbent.

## Separate teaching and native edit bounds

Each future authored source must include prerequisite concepts and an independent
practice world with disjoint addresses. Insert fills settings only. Apply and
Check remain explicit. Worked settings must satisfy the example's current and
failure outcomes; its documented experiment must break an outcome and repair
must restore it. Example Reset affects only the example. Whole-assignment Reset
uses the existing selected-attempt confirmation and retains other work/receipts.
Optional hints use the existing bounded hint counter; worked answers/references
are separate requests. No step counter or hint request controls mastery.

The native TextBuffer admits at most16 UTF-8 bytes per numeric/address draft,
without silent truncation. The complete packet is checked before any Apply,
Check, selector, header or probe action. A rejected/ignored insertion restores
native selection and deep Undo as well as the old draft; an invalid held gesture
remains vetoed through release. Modal/settings/data-tool state gates mutations.
Actual field sizes and shared controls must still pass runtime/reflow gates.

The pure core's16KiB state limit stays unchanged. The workspace bounds128 actions
per scope, eight clients, eight probes with eight events each,12 worked settings,
256KiB complete session,128KiB complete definition and1MiB source/Attempt context.
Each grade has at most588 bounded rows (one draft, two candidates, one role,
eight current clients and64 checkpoints of nine rows). Existing outer2MB pack
and16MB progress raw limits are not raised. Direct serde is not semantic admission;
raw session/definition codecs check their limits before parsing, and bounded
visitors refuse excess action/probe bodies. This is no general memory guarantee.

Native feedback memoization uses full Definition/Session equality after source
admission, never a self-carried successful badge. A later normal registration
must integrate source-aware library completion/index memoization and measure
warm frame/grade behavior before credit; this unregistered capability supplies
no such normal-course performance or certificate claim.
