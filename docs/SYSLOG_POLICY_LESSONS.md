## Teaching and interaction

The first task requires only recognizing an IPv4 address. Its introduction
explains events and history, all eight severities and inclusive thresholds,
independent local/remote outputs, facility versus subsystem, the delivery/filter
chain, and native Apply versus saved drafts. Later tasks recommend the previous
task, with the same essential concepts available in their introductions. Unit
prerequisite `ipv4-foundations` is advisory; introductions remain skippable.

The workspace has native source/collector selection and aligned policy fields.
Choose a source or collector, edit its fields, and explicitly Apply settings.
Generate simulated event creates evidence from an immutable supplied event.
Check configuration probes every authored positive and negative case and the
protected policies. Pending drafts are saved, distinguishable from applied
policy, and invalidate current completion. There is no learner terminal parser:
strict JSON in `Scenario.solution` is internal typed action transport, not IOS or
Linux syntax, and guide command arrays are empty.

Each task has a smaller separate Alder/Birch/Cedar-practice/Dahlia world with
different addresses and event IDs. A worked row fills settings without executing
them. Apply each row, inspect/generated evidence if useful, perform the precisely
described deliberate mistake, Check, then apply its repair. Reset example offers
a safe fresh start and leaves the assignment untouched. Main Reset remains the
existing confirmed reset; it is not an undo on a real device. Three task-specific
progressive hints, an explicitly requested worked approach and separate technical
references reuse R4's guarded help behavior. A hint alone must not reveal the
entire assignment solution.
