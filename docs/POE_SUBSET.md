## What the model represents

A source supplies power over a compatible Ethernet port to a powered device.
Power and data are separate requirements: an ordinary data-only port is not a
power source. The model uses supplied device classes, per-port source types and a
shared switch power budget. Source-side reserved power is **not** instantaneous
consumption or power delivered at the device after cable losses.

The supported source profiles are data-only, IEEE802.3af Type1(max15.4W) and
IEEE802.3at Type2(max30W). Classes0/3reserve15.4W, class1reserves4W, class2reserves
7W and class4reserves30W. A class4device needs the Type2profile in this activity.
These facts are supplied equipment descriptions, not measured classification or
negotiation. PoE++, UPOE, injectors, external supplies and physical signaling are
outside this first model.

## Deterministic behavior and limits

A plan attaches each device to at most one distinct supplied port and enables or
disables power per port. The model distinguishes disconnected, power disabled,
data-only, incompatible source, denied by shared budget and powered outcomes.
Only a powered device reserves its declared source-side class allocation.

**Teaching simplification:** reservations are recomputed in the supplied port
order. That order is visible and fixed; this is not a claim about a particular
switch's priority, admission, first-arrival or renegotiation algorithm. Earlier
reservations can leave too little budget for a later port. No automatic priority,
load shedding, LLDP/CDP, IOS CLI, actual voltage/current or network data-plane
behavior is simulated. A powered result alone never proves IP connectivity.

Eight ports/eight devices and a240Wsource-budget ceiling bound the model. Integer
milliwatts avoid floating-point rounding at exact boundaries. Invalid identities,
extra/dangling entries and two devices occupying one port are rejected before
observation. All evaluation is in-process over typed values; there is no host
file, socket, subprocess, electricity or system operation.
