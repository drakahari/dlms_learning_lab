# Native virtual syslog policy capability

This layer supplies a source-bound native workspace and private development
fixture. It adds **no registered curriculum labs** and no objective credit.
The supplied pure syslog model and this layer still need their actual gates;
source review alone is not runtime or beginner acceptance. CCNA v1.1 objective4.5
and future-version planning remain separate in the coverage map.

The interface preserves Introduction → separate example → full assignment.
The introduction teaches event/local/remote logs, increasing urgency toward
severity0, independent inclusive thresholds and the distinction between a
message subsystem and standard export facility. Example addresses and event IDs
are separate. Fill example settings populates only practice drafts; Apply settings
and Generate simulated event are explicit. Challenge keeps the same meaningful
assignment without unsolicited teaching/worked steps. Hints are progressive;
worked explanation and references are separately requested.

## Native interaction

Choose a source or collector. Source settings include process enabled for modeled
local/remote outputs, independent thresholds, a standard export facility and up
to8 collector-address rows. Collectors use a facility/threshold table. All24
standard facilities are offered with their actual numeric identities. Only16–23
are labeled local0–local7;0–15 use RFC5424's standard names. These are native
simulation settings, not an assertion that all IOS releases expose those CLI
keywords. No IOS/Linux terminal parser is implemented for this activity.

Apply settings validates the whole selected editor and commits atomically.
Blank, malformed or repeated addresses and unfinished/duplicate selector rows
receive specific feedback and remain editable. Changing a selector does not apply
it. Selecting another component preserves drafts. A pending edit is explicitly
labeled **Unapplied changes**; generated events continue to use the previously
applied policy. Apply updates the policy, not a host service.

Generate simulated event emits only the selected immutable supplied template.
The small source/collector preview is one configured destination; Check evaluates
every required case. Delivery facts are supplied simulation evidence, not observed
routing, UDP packets, clock or authenticated remote receipt. Default historical
views contain retained event rows rather than duplicate settings reports. Logs
are six font-derived rows with full-width scrolling; wide views place the editor
beside evidence and narrow views stack cleanly. The settings/table Apply action
stays outside scrolling rows.

Check configuration evaluates positive AND negative events against current policy,
not reference strings or old receipts. Allowed facility alternatives and thresholds
are explicit in authored targets. Protected policies are compared with supplied
initial policy. All applied/draft settings must agree to count as currently
complete. Editing a correct solution therefore clears current completion with an
honest pending-edit explanation. Old accepted records and checked flags cannot
keep an invalid policy successful. Clearing history alone does not break a still
correct policy. Separate example success never counts as assignment completion.

## Authoring and source authority

`syslog_workspace::Definition` holds immutable assignment/practice fixtures,
behavioral predicates, protected policy IDs and short structured teaching.
It has no canonical assignment answer stored inside the learner Session.
Session contains two current worlds plus independent bounded draft maps,
selections/view and feedback flags. Runtime history stores references to immutable
event templates. No rendered transcript or redundant initial-world copies are
persisted in this layer. The framework's existing bounded common Attempt history
remains readable/preservable but this native view does not generate, execute or
grade that text. The aggregate progress-limit development fixture uses that
legal common field, rather than creating a stress-sized model or real logs.

`Definition.shape` performs borrowed structural admission. Ordinary source/open/
context/save/render checks do not replay answers. The canonical source check
compares all fresh initial fields, building only small editor maps; it does not
clone full pure worlds every frame. `Definition.validate` additionally replays
only separate teaching steps and proves its experiment/repair. The existing
pack authoring validator alone replays Scenario.solution for assignment
reachability. A failed private solution cannot become a valid pack.

Scenario.solution uses bounded strict typed JSON action data internally, through
`execute_authored`: apply_source, apply_collector, generate, clear_local and
clear_collector. Native tools call the same typed adapter. These JSON values are
not learner shell syntax, do not appear as executable IOS/Linux examples and are
never passed to a host. Context-free execute refuses mutation honestly.

`source` requires exact State/Goal pairing, fresh canonical initial work and no
unrelated teaching metadata. `context` binds saved work to the authoritative owned
catalog definition/version and rejects altered event templates, delivery facts,
endpoint capacities or example identity. A state or its self-carried checked flag
is not its own authority. All-attempt source-aware saving includes inactive work,
missing/wrong sources and wrong State/Goal pairs; normal bare save refuses Syslog
work without its catalog. Existing atomic write/restore/provenance code remains.
Old labs, favorites, drafts, receipts and normal catalog counts remain unchanged.

Separate reset reconstructs only practice; selected Reset uses the normal confirmed
attempt reset. Native IDs include source/version/visit, assignment/example,
component and reset generation, preventing another activity/component's Undo state
from entering the current editor. Invalid text packets retain the full old draft,
cursor, selection and Undo; no character truncation. Ignored/oversized/aggregate
input, mixed Enter/Paste and held-button release cannot apply an old draft.

## Bounded resource and data limits

- Pure valid compact State ≤180,480bytes; its raw decoder cap is256KiB.
- Session has two worlds and two editor maps, capped512KiB; each editor ≤32KiB.
- Definition ≤768KiB; complete source/Attempt ≤2MiB, checked by streaming counters
  before candidate cloning. Current-field string and collection bounds apply to
  typed values as well as raw deserialization.
- At most32 source/event targets and a combined64 behavioral/protected rows.
  This extra native-adapter bound keeps fresh feedback below32KiB rather than
  creating a giant results dashboard. Each accepted remote target permits up to24
  explicit facility alternatives; negative targets require a non-accepted outcome. IPs/identifiers and the
  fixed explanatory outcomes bound each behavior row below400bytes;64 rows plus
  the short pending-edit row remain below32KiB. An exact defensive combined-text
  guard fails the entire check if that limit is exceeded, never drops failing
  rows or leaves partial success.
- Up to8 source drafts and8 collector drafts per scope;8 address rows of15bytes,
  24 selector rows. Bounded semantically unfinished drafts resume unchanged.
- Internal author action ≤2048bytes, below the existing4000-byte solution-entry
  limit. No messages or full models are embedded in actions.
- Existing whole-pack2,000,000-byte and progress16,000,000-byte bounds remain.
  Private tests intentionally exceed each aggregate cap with otherwise bounded
  synthetic data and require refusal/original preservation. A family maximum is
  not a promise that1000 simultaneously maximal histories fit a16MB profile.

No new dependencies, host process/filesystem/network commands, clock changes,
