# Retire unused service activation and protect secondary transfers

The two Linux labs follow listener auditing and DNS access boundaries.
Each teaches a worked method before separate guided practice and an
independent graded work order. The simulator reuses existing virtual
unit jobs, authoritative records, and secondary serial comparison.

## LPIC-1 110.2, one unused socket and its service

The service can answer in the current session. Its associated socket can
listen independently and start it on a supplied request. Enabled policy
controls later startup. The terminal supports literal one-unit `systemctl`
status, is-active, is-enabled, start, stop, enable and disable. The enable
and disable forms also support `--now` immediately before the unit name.
The same work order can be completed by separate stop and disable commands.

The virtual client requests use the modeled state and actual bounded
unit startup. A separate copied startup state checks whether the old
endpoint is still exposed and whether the required service remains
available. Observation results are distinct from current and future
policy. Supplied program descriptors and application config are fixed.
No socket is opened on Fedora. Real unit files, external commands, other
activation mechanisms, shadow passwords and TCP wrappers are outside this
subset. The shared simulator does not claim full systemd behavior.

## LPIC-2 207.3, one authenticated secondary handover

The inherited source-address rule may admit an unsigned request. A signed
request with an invalid supplied proof is rejected before transfer policy
is evaluated. Provisioned key references stand for already shared trust
material. The simulator uses no key bytes, signatures or secrets. This
exercise teaches the difference between authentication and authorization.

The primary and protected-zone editors each parse one `allow-transfer`
fragment. Allowed fragments contain `none`, the supplied secondary IPv4
address, or one known `key` with an optional quoted canonical name. The
existing checked tokenizer handles whitespace and comments. The DNS access
workspaces keep their earlier distinct ACL subset. No include is loaded.

After the learner applies the rule and matches a current supplied key on
the secondary, the modeled transfer updates the actual secondary serial
and record. A valid alternate current key can pass. A stale key with the
same name fails the supplied verification. Checks preserve the unrelated
zone, deny unauthorized cases and leave ordinary authoritative lookup
available. Syntax errors retain the earlier applied settings and copy.
The unrelated-zone requirement is checked with an independent current
proof. It can pass while the served zone still needs repair. A stale-key
failure alone provides no evidence that the unrelated rule denies entry.

No packets, host files, key generation, actual cryptographic verification,
clock checking, BIND execution, chroot/non-root service operation, forwarding
views, DNSSEC or DANE occur. Broader objective slices remain explicit.
