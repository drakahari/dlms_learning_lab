## Teaching and workspace

Introduction explains named fields/stanzas and the URI/suite/component relationship
before asking for edits. It demonstrates a separately named workshop configuration
and expected results. The recovery task builds on that syntax and explicitly
teaches independent refresh outcomes and the conditional usefulness of old lists.
These are selection excerpts, not complete authenticated source configurations.

Practice keeps its own draft, saved selection, cache, query and checks. Guidance
sits beside the editor, refresh evidence and lookup. **Fill worked source excerpt**
only fills that practice draft; it neither saves nor refreshes nor awards credit.
Learners change source selection after a successful lookup to see why retained
bytes do not keep an unselected source eligible, then restore and retry.

Assignment retains the full configuration task and exact requirement sentences.
The compact editor has explicit **Save sources**, **Refresh simulated indexes**,
and **Look up package** actions, actual source/cache states and actual lookup rows.
**Check work** grades current saved state and package provenance/version outcomes;
it does not match an answer string or require a prescribed command sequence.
Unsolicited worked answers stay hidden, including in Challenge. Completion is
independent of walkthrough position; edits invalidate stale checks. Query edits
clear stale lookup output without falsely breaking otherwise correct configuration.

Equivalent field case, stanza ordering, component ordering and repeated identical
targets pass where supported. Wrong Cartesian targets can fail overall while
individual correct cache/version outcomes remain met. The UI shows one overall
result, explains failing requirements and keeps the complete result list available.
