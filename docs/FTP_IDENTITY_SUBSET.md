## Contract before lessons

`ftp_identity_config` and `ftp_identity` are new opt-in pure modules. They are exported pure library capabilities over the unchanged production Unix
file model. No learner workspace or lesson is registered yet.
No daemon, socket, host command, host path, password validation or PAM is involved.
Supplied valid/invalid credential proofs stand in for authentication. Regular
virtual files and ordinary owner/group/other permission bits are real modeled
state; existing file engines/formats are preserved.

The finite configuration subset supports local_enable, anonymous_enable,
write_enable, chroot_local_user, chroot_list_enable/file, userlist_enable/deny/file,
download_enable, dirlist_enable and local_umask. Unknown options fail honestly.
Use the conventional option=value and YES/NO style in teaching. The pinned parser
also trims surrounding whitespace, accepts case-insensitive TRUE/FALSE and1/0,
and applies the last duplicate value. Comments start with # in column1; inline
comments are not supported. Permission masks beginning with0are octal, others
decimal; teach022rather than22. Values outside ordinary permission bits fail.
Configuration16KiB/128lines; paths512bytes/64components; no shell substitutions.

Local homes and the anonymous ftp home are supplied immutable fixture facts.
local_root, per-user configuration, guest remapping, writable-root overrides,
symlinks, special modes/ACLs, command filtering, TLS, PAM, protocol framing,
active/passive connection setup and real-server sandboxing are outside this
capability. None is silently approximated. Other existing transport work remains
separate. No claim of complete vsftpd, Pure-FTPd, ProFTPd or212.2coverage follows.

Saving unfinished bounded text does not publish it. Restart ends old connections,
then parses the saved text: failure leaves this simulated service stopped; success
publishes the new policy. This deliberately scoped full-stop/restart model is not
an emulation of a real systemd unit or the survival of already-forked FTP children.
Sessions are privately constructed and cannot be imported as privileged handles.
Virtual filesystem and source-bound workspace replay, rather than stored handles,
must restore learner work when integration is added.

chroot_local_user chooses the initial jail policy; an enabled exact-line chroot
list inverts that choice for listed users. The ordinary account list controls
login independently: userlist_deny=NOmeans an allowlist. Missing required lists
fail; a file full of similarly named users cannot match a substring. A confined
home becomes virtual `/`; absolute paths stay inside that root and `..` stops
there. Local login first needs search permission along the full home path. After entering
the jail, rebased permission checks exclude ancestors outside it. Component
walking still checks search permissions and existence before resolving `..`.
Non-confined users retain the global virtual namespace, so a chroot-list mistake
can demonstrably expose a readable outside file. A writable jail root prevents
login; provide a writable child instead. No chroot escape technique is modeled.

Operations: pwd, cd, names-only non-hidden listing, get and local put. Listing
requires directory read/search in this teaching subset. Downloads need file read
and parent search; anonymous files additionally need the other-read bit. Uploads
need the service write gate plus real file write or parent write/search rights.
Creating uses0666masked by local_umask and the supplied primary group. Overwriting
retains ownership/mode. Anonymous writes, mkdir/delete/rename/append, binary/ASCII
wire conversions and resume are unsupported. Transfers operate on supplied text
buffers, at most4KiBeach/32KiBtotal; no host/client filesystem. Negative operations
must leave file state exact. Maximum256entries/16accounts; finite bounded walking.
