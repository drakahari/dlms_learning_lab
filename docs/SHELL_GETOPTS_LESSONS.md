## Explicit input grammar and taught syntax

The first project receives ordinary argv. TAG and path values are single-line
text; quoted spaces, percent signs and literal pattern/backslash characters are
data. Supported short-option scanning, required arguments, clusters, end markers,
first-operand stopping, last-value policy, leading-colon diagnostics and shifting
the consumed prefix are explained before the assignment.

The later job files are **not command lines**. Each line is one whole argument;
a blank line is an empty argument, internal spaces stay together, and the last
line may lack its terminating newline. Lines have no leading/trailing spaces or
tabs, matching the disclosed default `read -r` behavior. Literal quotes and
backslashes are data. No embedded newline/NUL, eval, set, custom IFS, field
splitting or general shell-command parser is supplied or assessed. Existing
quoted dense-array reconstruction stores each line separately.

The reusable-job example explicitly teaches `local OPTIND=1`, local defaults,
function positional parameters, status and one deliberately shared description
result. Direct calls make scanner/default restoration relevant. The publication
example then teaches captured helpers: global option state already exists when
each child helper starts; local reset remains necessary, while emitted text and
status remain separate. Actual next calls and outcomes matter; no action history
or exact source spelling is a grading credential.
