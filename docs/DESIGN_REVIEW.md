# Approved workspace direction

The complete IPv4 assignment is the design reference: a short scenario, small topology, compact aligned form, one Check configuration action, targeted field feedback and optional hints/binary help. Its topology shows the entered second host and checked status; edits clear stale verification. It is integrated into normal launch, with no preview flag.

The same principles now apply to all nine labs: keep the whole assignment and appropriate tool prominent, preserve investigation and alternate solutions, and make lengthy guidance optional. Learn provides a short starting point; Challenge retains the complete task with less default assistance. Neither requires clicking through a wizard.

| Lab | Retained workspace |
| --- | --- |
| IPv4 | Whole subnet/second-host assignment and native fields |
| VLSM | All allocations in a table; row-specific diagnostic feedback |
| Gateway | Topology, interface/route investigation, repair and reachability testing |
| Permissions | Terminal inspection, effective access and alternate ownership/mode repairs |
| Traversal | Identity/path investigation and group/directory repair |
| Logs | Finding, reading and filtering modeled text in a terminal |
| Service | Journal/status investigation, config editor, restart/enable/verification |
| DNS | Native record/serial editor, saved/loaded distinction, validation/reload/query |
| Storage | Native persistent-device editor, capacity/mount investigation and cleanup |

The library retains certification navigation, topic and search, favorites, recent/resume and scalable pagination. Extra filters are optional; their active values remain visible when collapsed. The synthetic catalog remains a developer-only test fixture.

No new scenarios or dependencies were added. Scenario IDs/versions and saved work are retained with explicit optional-field compatibility handling. See [verification](VERIFICATION.md) for actual tests, native captures, migration details and limits.
