## Learning progression

**Configure, build and stage a kernel safely** follows supplied-source projects,
module options and boot-entry recovery. The existing prerequisite lessons and all
prior509scenario/205unit objects retain their IDs, values and order.

- `lpic2-kernel-root-build`: repair a saved configuration and derive actual modeled
  image/module outputs with working NVMe/ext4 root-driver prerequisites.
- `lpic2-kernel-staged-handover`: stage a different source's outputs, save an
  independent loader entry, verify root/init handoff and preserve a working fallback.

Each has an essential Introduction and worked example, separate guided practice,
and a full independent assignment. Worked source versions, UUIDs and virtual roots
are different. Reference operations are available only on explicit example review;
they never fill the independent assignment. Built-in and supported modular repairs,
different literal release suffixes and new entry filenames can satisfy the actual
requirements. A successful make operation alone cannot award completion.

The native workspace uses a configuration editor, source picker, bounded build
console, actual output list and, when relevant, staging/loader-entry controls.
Single-line fields inherit shared centered text/margins; multiline editors stay
top aligned. Columns reflow by font metrics. Expected worked output, actual run
output, unchecked work, partial failure and completion are distinct textual states.

## Supported configuration and supplied baseline

Only CONFIG_MODULES, CONFIG_BLK_DEV_INITRD, CONFIG_BLK_DEV_NVME, CONFIG_EXT4_FS
and CONFIG_LOCALVERSION vary. The five-setting fragment accepts y/n, y/m/n for
the two drivers, a quoted bounded literal suffix, comments and explicit not-set
lines. Unknown settings, duplicates, malformed values and unsupported expressions
fail clearly. A module choice with modules disabled is rejected rather than silently
normalizing it as though this were a general Kconfig dependency engine.

The supplied x86-64 baseline holds PCI, block support and other features/dependencies
available. Only declared NVMe/core and ext4/jbd2/mbcache inventories vary. These are
teaching fixture facts, not universal dependency lists or measured hardware support.
Kernel source versions are fixed worked values, not deployment recommendations.
Release auto-suffixing, source patches, full dependency resolution and C compilation
are outside the model. No upstream source, prose or assets are imported.

## Console operations

| Supported input | Actual modeled effect |
| --- | --- |
| `make` / `make all` | Image plus module outputs when module support is enabled |
| `make bzImage` | Image only; existing module outputs remain separate |
| `make modules` | Modules only; explicit request fails with CONFIG_MODULES=n |
| `make modules_install INSTALL_MOD_PATH=/staging` | Place matching module metadata in the chosen virtual root |
| `make help` | Explain the implemented subset; no output build or credit |

INSTALL_MOD_PATH can appear before or after the one target. Without it, module
installation uses virtual `/`, never the host root. Supported ordinary-space
variations are equivalent. Flags, tabs/control characters, quoted/expanded arguments,
shell operators, multiple targets, other variables/targets and recipes fail honestly.
This is a supplied-build console, not a shell or general GNU make/Kbuild evaluator.
Installing stale/foreign module records is explicitly refused; that restriction is
a simulator boundary, not a claim about arbitrary real make trees. Rebuild first.

**Stage image**, **Assemble build initramfs**, **Assemble staged initramfs** and
**Save entry** are named native simulator operations, not invented Linux commands.
No dracut, mkinitrd, mkinitramfs, compiler, installer or actual boot command runs.

## Derived state and grading

Builds bind exact source, base release, suffix and saved feature configuration.
Image, modules and early-userspace outputs are independent. Unsaved editor text
does not become build input. A later edit/build never retroactively updates an
older output. The UI and grader compare actual snapshots rather than command strings.

An initramfs binds its image and optional matching module inputs. Early userspace
can exist without loadable drivers. Modular root drivers need the supplied matching
module inventory; a missing installed module tree names its actual virtual path.
Previously assembled initramfs metadata retains its own inputs even if working
outputs subsequently change. Matching release labels alone cannot hide mismatched
source/configuration inputs.

Bare-device driver readiness can accept built-in drivers without an initramfs;
it does not prove a UUID-based boot. The unchanged existing boot-entry model uses
root=UUID= and needs supplied early userspace for UUID lookup even with built-ins.
Staging additionally verifies external-loading support and actual snapshot identity
before composing that shared boot trace. A working old fallback or changed entry
title cannot substitute for a staged candidate from the requested target source.
Every original fallback image, module tree, initramfs and entry must remain exact.

Configuration/entry/source/artifact changes clear stale checks. Completion is
recomputed from current outcomes after Check. Merely editing an unexecuted command
is not a change to the already-built system. Different scopes retain their own
unfinished drafts, histories, outputs and check state; reset affects only its task.
Saved source identity is checked against the authored catalog, without fabricating
answers or migrating old lessons to new requirements.

## Bounds and isolation

Configuration8192bytes, entry4096bytes, command2048bytes; one native action16KiB.
Task source identity65536bytes, at most two supplied sources and24reference actions.
Each staged descriptor family is capped at eight entries; console history128lines.
Paths/text are bounded and canonical; duplicate or ancestor file conflicts fail.
State mutations validate a copy before commit. These are typed virtual descriptors,
not executable kernel images or initramfs archives. There are no learner host-file,
subprocess, network, service, firmware, boot or system effects. No dependencies or
existing shell evaluator behavior are changed. Internal author/native action routes
are not taught as Linux commands.
