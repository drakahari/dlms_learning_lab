## Learning progression

Introduction teaches six mount-table fields, UUID versus changing device alias,
read-only access, automatic requests and optional dependencies. A complete separate
workshop/camera example precedes the option/reason table. Try example preserves a
separate editable draft: inspect intentional faults, repair the policy, then add
nofail to required workshop storage and explain the resulting failure.

The independent assignment keeps project storage required/read-write and audit
media automatic/optional/read-only. Three deterministic presence/alias samples
check actual intended mounted volumes, access and dependency policy. Losing the
required volume must remain a visible failure; making every request optional,
emptying the table or using noauto cannot satisfy the task. Alternative supported
option order, defaults and supplied aliases are accepted where their outcomes fit.

The report separates **task requirements** from **actual mount attempts**. A task
can correctly protect required storage while the selected absent-required sample
still displays a failed mount. Syntax errors never count as that expected outcome.
A wrong UUID retains one legitimately passing absent-media case while failing two
present-media cases. Current success is derived again from the checked current
source, not trusted serialized result text.
