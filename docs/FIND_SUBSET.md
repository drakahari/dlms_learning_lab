Supported grammar:

    find START [-maxdepth N] { -name PATTERN | -type f | -type d }* [-print]

Exactly one explicit start, up to16 implicit-AND name/type tests, optional unique leading maxdepth and optional unique final print. Without print, matching paths are printed. A start may be an ordinary file or directory. No default/multiple starts, --, print before a later predicate or repeated print; these otherwise meaningful real-find forms are explicitly outside this slice. Use ./-name for a literal path beginning '-'. Depth0 means the start alone. N is1–10 decimal digits, value0..2147483647, with leading zeros permitted within the token bound. All syntax is validated before traversal. General operators/actions, execution/deletion/pruning, size/time/owner tests, links/follow flags, mount boundaries and advanced formats are rejected.

The existing terminal removes literal quotes/backslash quoting and rejects unquoted shell *? expansion. For example, find . -name '*.log' passes a wildcard pattern to find; quotes protect it from shell expansion, not from find matching. Name patterns match the whole basename: literal UTF8 bytes, * for zero-or-more bytes, ? for one byte and backslash quoting the following byte. Leading dots are not special. This is fixed C-byte matching, not Unicode-character or locale emulation. Unescaped square brackets and trailing backslashes are unsupported; escaped brackets/wildcards/backslashes are literals. File contents are never inspected. No regular expressions, classes/ranges or extended patterns.

Display paths preserve START exactly, including ./, trailing/repeated slash and .. spelling. Lookup separately uses Tree's component-by-component canonical resolution and existing already-open working-directory semantics. Start basename is taken from the entered spelling after trailing slashes; root has basename '/'. Thus find . -name . selects the start. Descendants append one separator only when START lacks a trailing slash. Hidden entries are visited, but no synthetic . or .. descendants are generated. Deterministic byte-sorted preorder is a simulator ordering choice, not a promise that native filesystem enumeration is sorted. Literal path plus newline output models non-terminal find output; GNU tty-dependent escaping is excluded. Existing Tree paths cannot contain newline/control/NUL characters.

File read permission is not required for name/type matching. Initial path resolution requires directory search on its actual components. A reachable directory can itself match without permission to read its contents; maxdepth0 avoids every unneeded descent check. When descent is requested, an unreadable directory yields a PermissionDenied diagnostic and no children are inspected. A readable but nonsearchable directory yields explicit UnsupportedTraversal and is skipped, rather than a false successful empty result. GNU readdir/type/stat optimizations are backend-dependent; this model does not assert all name/type searches universally need r+x. Healthy sibling subtrees continue. Failing a name/type predicate never prunes descent.

Tree::find takes already-separated operands (excluding command name) and returns a nonserialized bounded FindReport with matched paths, structured FindDiagnosticKind/messages, suppressed-diagnostic count and complete(). It validates the existing Tree, argument counts/bytes and grammar before creating query data. Complete reports become the normal terminal Ok text. Incomplete reports become terminal Err text explicitly labeled 'Search incomplete. Partial matches:' followed by paths and labeled diagnostics. This preserves useful partial results through the existing one-text-result/error API; it does not emulate separate stdout/stderr streams, numeric exit codes or byte-identical GNU errors. Query errors never earn completion through history/event authentication; this extension adds no grading requirements.

Every success/error preserves the entire Tree and its serialized shape: nodes/files/users, modes/ownership, current/home/previous directory, umask, clock and modified timestamps. Query execution is read-only, avoiding the mutation candidate's copy of file contents. Other Tree commands and legacy permission/log/script models remain unchanged. No new root/ACL/SELinux/capability/mount/descriptor model is implied.

Existing bounds remain256 entries,1024-byte canonical paths/64components,4096-byte command and32KiB terminal output. Added query bounds:255-byte pattern tokens,16predicates,1,048,576 charged traversal/comparison steps,2048-byte displayed labels,512KiB total pending labels and256 bounded pending items. Iterative depth-first traversal and two<=256byte-name Boolean DP rows avoid unbounded recursion. Pattern parsing does not clone direct oversized inputs. Report buffers check before growth, reserve384bytes for limit/error headings, retain at most16diagnostics of512 UTF8-safe bytes each in fresh allocations, and explicitly count suppressed diagnostics. Limits produce incomplete output with a typed limit diagnostic, never silent truncation/success; paths already accepted are preserved. A terminal report's complete text stays<=32768bytes. Files are neither read nor copied by the query.
