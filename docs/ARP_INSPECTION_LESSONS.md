## Workspace and observations

The native page uses the shared topology, single-line fields, dropdowns and control
metrics. VLAN/trust settings, exact address-list editing or field comparisons are
prominent according to the task; other settings remain optional. Address-list
columns reflow into labeled fields. Additional rule ordering is optional. Packet
fields appear beside Replay; Ethernet/ARP comparisons are immediately visible
when essential. Actual output has eight text rows and its own scroll area.

Every sample first observes its supplied DHCP Request/ACK, then sends real typed
ARP metadata through the virtual Ethernet engine. Protocol labels distinguish
DHCP setup, ARP and explicit clock changes in output. Replay starts a separate
sample network and replaces previous observations while keeping the policy draft.
Check work runs every traffic case separately and leaves displayed observations
unchanged. A displayed binding table alone is not completion credit.

Case results show an overall verdict, named Matches/Needs work rows and a specific
first mismatch; remaining observations are optional. Partial MAC repair still
exposes the DHCP-fallback fault. Source-only comparison still exposes the reply
mismatch. Incorrect/unapplied edits clear current success. Parsing errors retain
unfinished draft text and identify the offending address-list field.

## Simulation and source boundaries

See [DAI contract](DAI_SUBSET.md). This is one supplied access switch, ordinary
virtual recipients, confirmed DHCP records and ordered exact IP/MAC rules. It is
not IOS, a host ARP cache, ping or device authentication. ARP trust and DHCP trust
remain independent. The supplied DHCP policy is read-only in these lessons.

Zero-sender special handling with the optional IP check off, copied valid pairs
on another port, wildcard lists, trunks/stacks, full rate/log/counter scheduling,
IPSG and equipment conformance remain excluded. Unsupported behavior is diagnosed,
never assigned a guessed pass/drop result. A request's unknown target MAC is a
separate supported case. The eight-arrival resource guard is a simulator limit,
not hardware rate/error-disable emulation. Nothing runs on a host network.
