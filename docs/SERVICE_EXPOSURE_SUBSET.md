## Supported behavior

A task supplies one unicast IPv4 server, one virtual interface and one to eight
named observer positions. The path outside this host is a supplied reachable fact;
this model does not discover a network. TCP observations derive from ordered INPUT
and OUTPUT decisions and the current supplied listener owners. A dropped request
or response produces **filtered**; an allowed exchange without a listener is
**closed**; an allowed exchange with a retained listener is **open**. None proves
application health, an identified software version, vulnerability or safety.

The existing process simulator supplies ps/pgrep/kill/renice and numeric listening
ss behavior. Pausing an owner retains its sockets; ending it removes them. A paused
owner with pending termination retains its socket until the modeled lifecycle ends.
Queue evolution, actual handshake timing and application exchanges are not modeled.
The numeric filter parser/evaluator is reused; only the supplied interface can be
named. Firewall commands require the supplied root identity; sudo/login are absent.
Valid partial process-command failures retain their actual effects and exit status.
Unsupported syntax fails honestly and never reaches an operating-system process.

The finite simulated scanner grammar is:
```text
nmap -n -Pn -sT -p PORT[,PORT...] SUPPLIED_IP
```
Options may be reordered. Numeric output (-n), bypassed discovery (-Pn), TCP connect
(-sT) and an explicit finite port list are required. Each observation uses the
supplied client source address and a fixed simulated source port40000. At most32
distinct ports1–65535 are accepted. The server address must match the task exactly.
There is no hostname, arbitrary target, port range, UDP/raw/ACK scan, NSE script,
service/version identification, operating-system detection, DNS, host discovery,
real packet, socket or subprocess. Output is explicitly a simulator report, without
invented real Nmap version/timing/banner data or port-number-based vulnerability
claims. The full Nmap command language is not implemented.

Task grading combines source-pinned process preservation/retirement, actual probe
outcomes and existing bounded semantic CIDR/port-domain filter comparison. Successful
samples alone cannot establish an entire policy: allowing only displayed client
addresses or denying everything must not pass. Useful required access must work.
Equivalent supported policies and signals should pass where they meet all outcomes.
