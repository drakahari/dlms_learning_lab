# CCNA evidence and access-policy subset

These two lessons practice parts of v1.1 objectives 5.1 and 5.2. Each
provides a worked example, a separate native practice workspace, and a
graded assignment with different evidence or access needs.

## Change investigation

The journal is a bounded, supplied set of typed records. The learner
compares approved and applied revisions, finds a later client observation
on the same relay and distinguishes reaching the sign-in boundary from
a successful use record. Source validation insists that the affected
restricted client actually reaches the boundary under the starter
policy in the virtual route model.

The editor reuses the bounded IOS-style management configuration parser
and in-process IPv4 path and admission engine already used in the remote
management unit. It applies an 8 KiB draft over the provided relay and
known clients. A rejected apply preserves the previous virtual policy.
Native checks cover both intended access and intended denial. The
model has no real login, packet exchange, vulnerabilities to reproduce,
external targets, attack emulation or system changes.

## Protection policy

The virtual facility table applies a selected access rule to an approved
role, staffed or after-hours window and escort status. Trial results
distinguish allowed work, scope or escort denials and audit records.
A supplied unexpected-contact report must reach the security desk. More
than one report route can satisfy the policy. Both assignments expose
their own evidence and result checks without credit for practice.
No real badge systems, fixtures, facility procedures, credentials,
active monitoring, external messaging or incident handling are involved.
