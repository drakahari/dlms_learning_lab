## Supported model

One exact installed package record supplies expected mode, owner, group and modified
time for its declared ordinary text files. The pure restored_metadata API validates
the State/identity, preflights every payload path before cloning, then returns a
validated State with only those four fields repaired. All contents, installed
identities/versions, dependencies, cache, source Catalog and unrelated files remain.
It uses the actually installed archive, not an available/published newer version.
Repeated repair is a no-op. It cannot recreate a missing file or repair contents.

Metadata/content are distinct typed outcomes. OwnedMetadataMatches compares only
mode/owner/group/time and explains the particular differences. PreserveInitialContents
keeps intentional site text even when other attributes change. Existing full payload
comparison still detects changed content. A zero command status or saved transcript
is never the grade. Current checks recompute live file/record outcomes.

An authored Definition must opt in with allow_metadata_restore=true before the closed
console accepts rpm --restore NAME. Missing flag defaults false and serializes absent,
so existing definitions keep their representation and command refusals. Default
parse/validate_guidance remain closed; source-aware parsing is used only through the
validated caller-held Definition. Saved core State or Session cannot enable it.
Metadata requirements without the source capability are rejected. Teaching and
assignment capabilities must agree, with separate catalog/filename namespaces.
No new Action, State format, progress migration, dependency or shell evaluator exists.
