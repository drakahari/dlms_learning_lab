## Meaningful assignment and teaching

The learner configures an inherited `EDITOR` from each supplied
`PREFERRED_EDITOR`, preserves `TEAM`, inspects actual child behavior, and uses the
selected simulated editor to maintain a saved handover file. Three deterministic
environments include absent, already inherited and empty editor values, with both
supported preferences. A private assignment can accidentally appear correct in
an already exported environment; it fails the sample with no existing export.
Hardcoding one name, printing a look-alike report, unsaved edits, duplicate records
and lost unrelated lines cannot satisfy the complete assignment.

Introduction explains shell values/export, supplied versus created variables,
application-specific editor conventions and saved-file verification. Its worked
training handover uses different records. Try example runs an intentionally
incomplete setup, offers inert **Fill worked setup**, and gives contextual editing
instructions. Assignment retains the full practical task, independent script and
file drafts, with optional hints. Challenge hides unsolicited walkthroughs.

The native workspace keeps the setup script, Run/Stop, actual results and editor
handover together. The file editor opens only after actual setup behavior passes;
it is the existing bounded vi-style surface, not a selector pretending to edit.
Changing setup invalidates its launch/check while retaining file work. Beginning
a new run also clears previous success before any instruction executes.

## Fidelity and isolation

`editor_handover` composes the existing environment VM and modal-file models.
There is no new shell parser, evaluator revision, utility, dependency, host
environment, process, editor launch, file access or network route. Exact `vi` and
`vim` data values select the same disclosed bounded editor. Paths, flags, nano,
Emacs and arbitrary program names are not executed or silently emulated.

This simulated handover application consults `EDITOR` only. Real applications
can honor `VISUAL`, `EDITOR`, application settings and different defaults; this
is not a universal precedence rule or a change to the desktop's default editor.
Nano/Emacs awareness is supporting explanation, not hands-on emulation. General
vi operators, complete Ex, counts, regex and other unmodeled behaviors stay gaps.

Setup reuses the existing8KiB source/2,000-instruction-per-sample/output/expansion
limits and cooperative16-unit UI advances, plus the whole environment-job bound.
Stop cancels only that in-process job. Virtual editing retains its existing
4files/4KiB-per-file/key/search/undo limits. Combined saved work is bounded to
3MiB and pinned to its bundled identity/definition; pack/progress outer bounds
also apply. Declarative `editor-handover` JSON events are authoring data, never
Linux commands taught to the learner or a host execution bridge.
