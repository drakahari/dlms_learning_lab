The task differences concern directionality, field scope/staleness, a per-port transmit-only policy and a multi-attachment recovery. They are not numerical variants. Every assignment supplies the requested operational values and preservation policy; recognizing a reference action sequence is never a grading requirement. Different valid configuration orders, sending orders and refresh counts are accepted by current-state requirements. An endpoint identity or attachment change is rejected, even if a similar-looking cached record exists.

Each Learn introduction supplies four short skippable concepts, an editable example with different device IDs, native-action wording, progressive optional hints and a worked explanation. Practice is cloned and saved independently from the assignment. Filling the example projects only configuration into its draft; Apply settings does not schedule information advertisements, and explicit manual time never sends them. Configuration lifecycle can still remove records, including the graceful stop modeled when Transmit is disabled. No practice result awards assignment completion. The native neighbor details expose chassis/port IDs, optional advertised fields, age and remaining TTL; displayed names are not the fixed identities.

Examples and runnable changes are distinct:

- A sensor/collector receive repair, followed by an exact eight-second expiry of both records.
- A labeler/index metadata refresh, followed by the new seven-second sender lifetime expiring while the reverse sender’s twenty-second record remains.
- An edge/desk transmit-only policy with a separate healthy auditor; advance one second and attempt a send from the disabled transmitter while inbound/healthy records remain current.
- A smaller reader/builder handover, followed by a second requested hub rename and refresh from both hub ports.

All example/try-change plans use supported configuration, Send now and positive manual-clock actions. No authored solution, example or change asks for an explicit withdrawal command/control. Pack-only `discovery ` plus JSON reference actions exist solely to validate reachability and are not copied into learner guides, hints, explanations or the native editor. There is no IOS command interpreter or command-to-success string matching.

Every assignment includes one exact whole-configuration requirement in addition to current-neighbor/absence outcomes. This preserves link-up state as well as unrelated global and port settings. Granular global/port snapshots alone would not preserve a link; absence cannot prove that the intended transmit policy caused it. A positive record must have the expected direct peer, positive remaining TTL, present deliverability and advertised fields matching the current sender. Historical data or a missing/aged-out row cannot count as current. These simulator-only current checks are not an authentication of past events or a physical-network guarantee.
