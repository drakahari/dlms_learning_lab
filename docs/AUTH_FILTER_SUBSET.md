## Purpose and boundary

A filter describes which application-log lines indicate failure and which explicit
exceptions should be ignored. Matching alone does not ban an address, establish an
intrusion, run a daemon or prove working protection. This first slice tests bounded,
source-owned application messages in memory. It does not install or run Fail2ban,
Snort, OpenVAS/Greenbone, a firewall, an operating-system utility or a host command.
No source path, process, network, personal-file or live-log interface exists.

`log_filter::Filter::parse` reads a small text definition. `inspect` returns actual
matched/ignored/missed observations with original line numbers/text and a numeric
IPv4 token where present. It validates the entire definition/log input before
returning observations. An unsupported input or exhausted allowance returns a
separate error, never a partial report or successful check. Grading/persistence/UI
integration remain separate work; no old State field or grading rule changes.

## Supported definition

One `[Definition]` section; one `failregex` setting; optional one `ignoreregex`.
Full-line `#`/`;` comments, blank lines, name=value spacing and `; ` inline comments
are supported. Empty ignoreregex means no exceptions. Duplicate settings, other
sections/settings, continuation lines, includes, interpolation, date formats and
executable actions are refused explicitly. The fail pattern has exactly one
unescaped, unquantified mandatory `<HOST>` outside groups/bracket classes. No
top-level alternation may bypass the tag; groups/alternation in other fields are
supported. Surround it with literal spaces (or an =/: prefix), or line anchors.
A pattern must require the complete address token, not an optional/partial capture. Ignore patterns have no
address tags. Each source line has at most one canonical numeric IPv4 token; names
are not resolved. Multiple candidate addresses are an explicit unsupported case,
not a guessed capture. Timestamp processing and multiline logs are not supported.
Timestamp-free messages are suitable for this filter-test slice, not daemon setup.

The matching language is an explicitly checked common **ASCII** regular subset:
literals, ordinary grouping/alternation, dot, anchors, ordinary quantifiers,
explicit bracket characters/ranges and escaped literal punctuation. Existing ERE
compiler limits further restrict expansion/repetition. Python shorthand escapes,
backreferences, lookarounds, inline flags, named/special groups, lazy/possessive
quantifiers and POSIX named/collating/equivalence classes are unsupported. Never
present general Python regex and POSIX ERE as interchangeable. The existing bounded
pure ERE graph is reused only after checking this smaller overlap. Source logs have
one numeric IPv4 token, so substituting its escaped literal into `<HOST>` tests the
same boolean condition without pretending to support arbitrary capture selection.

Ignore patterns are tested before failure patterns. A matched ignore pattern gives
Ignored; otherwise a matching fail pattern with a canonical address gives Matched;
otherwise Missed. These are actual observations, distinct from expected teaching
rows. A model error never counts as a correctly excluded line. Terminal/parser/file
workflow support is not claimed by the current pure model.

## Resource limits

- Definition2KiB; each pattern192bytes; log64lines; each line512ASCIIbytes.
- NUL, embedded line breaks, CR/control bytes and non-ASCII messages refuse.
- Existing ERE graph/node/depth/repetition/storage limits remain unchanged.
- One report shares250,000compile/matching work units, below the existing matcher
  maximum. No unbounded backtracking, recursion over log input or partial report.
- Returned source text is at most32KiB plus bounded row metadata. There is no
  learner-controlled file creation or external action.

These limits are part of the disclosed subset, not complete Fail2ban fidelity.
