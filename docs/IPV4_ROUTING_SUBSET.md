# IPv4 static-forwarding contract (M29)

Specified2026-10-22 before implementation. Add a pure bounded IPv4 routing capability alongside the working IPv6 module. Do not generalize/change the IPv6 state or original IPv4 assignment, add a dependency, or count new curriculum until native integration and substantive lessons are reviewed.

## State and scope

Typed named devices, interfaces, fixed physical link identifiers, optional IPv4 address/prefix assignments, up/down and forwarding states, and fully specified static routes (destination prefix, outgoing interface, immediate next-hop address, administrative distance). At most12 devices,8 interfaces/device,32 routes/device and16 forwarding hops/path. Validate bounded identifiers, unique map keys and bounded arrays before accepting decoded topology; reject malformed/unknown fields. Current private RFC1918 and documentation RFC5737 ranges are supported for virtual endpoint assignments; this does not assert Internet allocation/reachability. No host networking, file I/O, process or shell API.

Routing prefixes support /0 through /32 with correct32-bit masks/alignment, including /32 host routes. Interfaces use conventional /1–/30 subnets. Network/broadcast interface assignments remain representable as broken configuration but cannot send/receive successful unicast probes. The existing subnetting assignment’s /31 and /32 exclusion stays unchanged. RFC3021 point-to-point /31 interfaces, loopback /32 interfaces, unnumbered interfaces and public/special-address policy are explicitly unsupported in this first forwarding model; do not teach blanket network/broadcast subtraction for all IPv4 uses.

## Forwarding and verification

Derive connected routes only from up, usable interface assignments; local delivery is exact current ownership. Choose longest matching destination prefix, then lower distance for equally specific candidates (connected0, supported static1–254). Distance255 is not eligible. Next hops must be usable host addresses within the outgoing interface’s connected subnet and must not equal any configured local interface address, including a down interface; recursive next-hop resolution and interface-only static routes are outside the initial subset. A missing neighbor does not withdraw an otherwise eligible static route or trigger a backup: neighbor discovery/liveness is not a routing protocol. A down outgoing interface makes its candidate ineligible. Up/down is supplied modeled operational state per interface, not automatic Ethernet carrier detection; a two-ended link failure fixture must set the relevant ends explicitly. Equal-cost distinct choices fail with an explicit unsupported diagnostic rather than selecting arbitrarily.

Resolve an exact up neighbor address on the selected physical link, diagnosing duplicates, self next hops, non-forwarding transit devices, loops, absent neighbors, missing routes and return-path failures. Both forward delivery and reply must work. Source selection is the chosen outgoing interface’s usable IPv4 address, not a claim of complete host/router source policy. No ARP packet exchange/cache, MAC learning, actual ICMP/TTL/timeouts, transport session, ACL/NAT, proxy ARP, dynamic protocol, ECMP, VRF/PBR or real device CLI is modeled. Link adjacency is typed lookup, not host networking.

Grading integration must name the intended destination device/interface as well as its configured address and check the reached owner, so relocating a target IP to an intermediate router cannot earn endpoint reachability. Preserve required endpoint/subnet assignments separately where the task demands them. The named target interface supplies the address; ordinary weak-host local delivery is not ingress-port pinning. Fixed-address/subnet requirements remain separate from endpoint verification. Positive service cases and controlled up/down test overrides derive from current state; overrides clone state and never repair saved configuration. Fixed device/interface/link shape remains immutable on import. A bare failed probe is never a negative-policy success.
