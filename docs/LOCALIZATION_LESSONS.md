## Teaching and interaction

Each Introduction teaches the concepts and explains a different worked example.
Locale practice puts the sample application/terminal beside the saved-defaults
editor. Encoding practice pairs the terminal with an actual-byte document viewer.
Action-specific guidance sits beside those tools. Worked insertion/filling is
inert and available only in practice. Assignment and Challenge preserve the full
task without unsolicited worked commands. Example and assignment drafts, command
histories and checks remain separate.

Reports are an original simulator demonstration, not a Linux command. The six
normalized locale categories and explicit supported command forms are documented
in [the subset](LOCALIZATION_SUBSET.md). A new login reads saved defaults; it is
not a child terminal inheriting the current process. Conversion stdout does not
save a file unless an output is requested. A failed conversion can leave a real
partial virtual file; its status and contents remain visible for diagnosis.

Feedback distinguishes parsing, unsupported behavior, executed failures, unsaved
configuration, incorrect report behavior and wrong/missing output bytes. Passing
individual cases cannot hide an unsaved configuration requirement. Edits that
break work invalidate current success; unsupported commands that change nothing
do not fabricate a state change.
