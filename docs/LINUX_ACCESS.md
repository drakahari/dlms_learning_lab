Authored2026-10-22 against LPIC-1 5.0 objective104.5, building on the six file-management foundations. Four distinct assignments use the ordinary-user permission model; the original private-file/traversal/log seeds remain intact and follow this unit. Prerequisites are advice, not locks.

Learn introduces the needed concepts and commands before testing, with separate saved practice trees, different example values and exact suggested experiments. Two experiments intentionally fail: creating a new name in a550 directory and renaming after restoring a500 parent. Failure retains the example tree. Challenge keeps the complete task/terminal without unsolicited walkthroughs. Optional help supplies separate command examples, progressive hints, reasoning, sources and limits.

Grading checks current typed state, access for supplied subjects, retained content/modes and owner/group metadata. A copied/recreated file cannot pretend to be another owner's original. Missing/wrong-kind access targets never satisfy a denied-access goal. Supported numerical/symbolic changes and different valid command sequences pass; broad permissions, mode-only/group-only changes, wrong/incomplete updates, copy-delete replacement, missing cleanup and damaged evidence fail. Examples earn no assignment credit. Drafts and attempts roundtrip under existing progress schema/IDs/versions; only the selected reset changes its two workspaces.

Limits: one ordinary simulated user, fixed supplied groups, traditional permission bits and virtual text files. Root/account changes, ACL/SELinux, special mode bits/files, links, mount policy and real multiuser processes are not modeled. Informational id uses synthetic numbers. chmod is explicitly scoped; chgrp requires ownership/membership. The first task assesses read/write of text, not execute permission. A drop folder without browsing is **not** a secure upload-service design: known names and directory write/search have removal implications. Textual/canonical-path checks do not imply real link/alias safety.
