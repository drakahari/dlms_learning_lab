# Make existing LVM storage available

Two distinct LPIC-2 lessons follow raw retirement. They preserve the accepted
Introduction → separate practice → independent full terminal assignment pattern.

| Stable ID | Practical task |
|---|---|
| `lpic2-lvm-activate-data` | Recover access to intact but inactive data without rebuilding storage or activating a deliberately inactive neighboring pool. |
| `lpic2-lvm-availability-handover` | Make the requested data available while taking an unused raw pool offline and preserving the already-open live service. |

Introduction distinguishes metadata/allocation from availability, teaches the
named-group y/n forms, shows different worked values and explains that mounting,
boot policy and actual process checks are separate. Native per-LV states use
Active/Inactive/Marked open wording. The command picker provides individual
explained actions; Insert selected command never runs them. The guided reader
shows an unavailable result until activation, then original retained contents.
An explicit adverse availability change breaks the worked result and a focused
repair restores it. Example work never awards assignment credit.

Assignment keeps all requirements visible, the appropriate terminal and current
state prominent, and worked commands hidden by default. Challenge retains the
same meaningful task. Feedback names an incorrectly changed unrelated LV rather
than blaming all preservation at once. Reader feedback distinguishes unavailable
storage from readable-but-changed contents. Current truth invalidates after a
bad change; prior walkthrough position is retained honestly.
