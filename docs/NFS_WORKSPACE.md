# Bounded NFS application and separate practice

Stage A library gates were accepted before this Stage B source proposal. Stage B
adds typed State/Goal and optional saved Session/Learning hooks, catalog-aware
admission, atomic application actions and old-family rejection. The combined Main default regression passes 1851 checks with no failures;
scoped NFS persistence/isolation and cache guards pass. Actual native NFS
rendering and authored lesson acceptance remain separate gates. No native renderer, terminal,
normal NFS registration, dependency or objective status change is included. All
147 existing activities/37 units and historical source fixtures remain exact.
The technical JSON is an unbundled developer fixture, not a bundled lesson or a
claim of novice/native acceptance.

The accepted pure NFS core remains unchanged. All operations concern supplied
numeric identities and in-memory existing files. There is no host mount, filesystem,
server, RPC, network, shell, real utility output, errno or numeric NFS status.
See [NFS_SUBSET.md](NFS_SUBSET.md) for the exact parser and ACCESS-style boundary.

Server draft/saved/applied exports and client draft/saved/current mounts are
separate. Save retains bounded malformed text without applying or mounting it.
Apply changes the typed table only; incompatible live bindings require an explicit
Unmount under the model's conservative planner rule. Allowed writes replace an
existing file's actual current text, not its metadata or a solved-state flag.
Inode ownership/mode/path inventory is immutable: no chmod, chown, create, delete,
rename or open-handle capability repair is available. Initial supplied paths must
already permit the intended supported repair. Wrong missing-search cases are
negative diagnoses, or can be repaired by selecting an eligible supplied numeric
profile or a supported anonymous-group mapping; never by pretending to change an
inode. The technical fixture demonstrates both legitimate repairs without changing
any Inventory byte.

`Definition` pins the entire initial Inventory, not merely its fixture label.
Typed rows check actual current mounts, required current text, access decisions,
relevant committed documents, named saved mount presence/absence and explicit
initial mount/file/layer preservation. Positive current reading or a current
mount plus actual required text, and positive new-mount file access, are mandatory.
An empty/all-denial goal cannot pass as a useful service. File permission alone is
not publication. Alternative policies/actions can satisfy the same rows: no whole
Runtime match, reference command order, action counter or transcript grants credit.

Only explicitly required document rows carry pending semantics. A committed server
row requires draft==saved and semantic equality of parsed saved/applied tables;
export/root and disjoint-clause order are ignored, while exact normalized selectors
and options remain meaningful. A saved client row requires draft==saved and a full
successful parse. Malformed saved text is never absence. Unrelated bounded raw
drafts can remain as supplied. Request selection, relative-path text and an unsent
file replacement have no grade meaning. Changing an unrun query does not revoke
correct applied outcomes.

Each grade vector caches every relevant server/client saved parse once for direct
rows. One core Evaluation batches all current access requests and independent
fresh trials, which operate on one private scratch State at a time. The unchanged
core may parse saved documents again for its independent Saved trials; that is not
one serialization per requirement or a cached authority. Current mount/file/access
rows may all remain healthy while Saved trials fail. Explicit saved/committed rows
must also fail malformed/pending saved policy, rather than being called healthy.
Checks never create a required live mount or publish required live bytes.

Expected Denied matches only a Decision::Denied with its exact stage. Faults,
including unsupported identity/context/parser/limit failures, are false outcomes.
Client ro then export ro gates remain defined write denials before numeric mapping.
An unsquashed UID0 read or rw permission path remains Unsupported and cannot satisfy
an expected denial. Root squashing independently maps zero UID/GIDs; anonymous-owner
access is a positive counterexample to treating it as deny-all-root.

The display-only Session retains supplied selections, bounded raw request/write
fields and at most16 derived operation/read display entries. There is no invented
command console or failure number. Oldest display entries alone may evict to fit;
script records, migration receipts, other attempts and favorites are never evicted.
A borrowed proposed entry array is measured with a checked streaming JSON writer
before copying retained entries or read text. A failed core operation leaves both
State and Session exact; callers may display the returned bounded error separately.
One admitted State candidate is copied for an actual app operation; only the
bounded candidate State and Session commit together. No whole Progress snapshot.
Stage B additionally preflights the proposed complete Attempt before commit.

Separate Lesson data owns its own Definition and initial State once, not a second
redundant fixture. Examples use different server/client/profile IDs, addresses,
root/file/local paths and values. Learning retains that exact context, evolving
State, independent Session, view/selection and a presentation checked bit. It never
installs the example result into assignment work. Fill only changes editor/request
values; Save/Apply/Mount/Read/Write still need their explicit controls. A retained
checked bit or past read cannot override a fresh negative current grade. Reset
returns only that practice to its supplied initial context. This Stage B proposal
adds full app preparation, old-attempt first-open Assignment, generic progress
admission, saved backup readback and reciprocal foreign-family checks. Native UI
lifecycle remains deferred.

The technical fixture has four different shapes: restricted reference export,
publication diagnosis, explicit replacement-client handover and two-share handover.
Each has a separate worked example/experiment/repair and two source-authored valid
plans. Tests cover host/CIDR and action-order alternatives, immutable metadata,
current/saved/fresh independence, exact denial/fault distinctions, full context,
semantic ordering, strict decoding, escaped frontiers and atomic refusal. These
are independently authored expectations, not observations from a host NFS system.
Every test/reference/example must be executed by Root before acceptance.

## Stage B source frontier

New optional fields omit None during serialization; older activities retain their
wire representation. Current checks and catalog-aware decode pin Scenario version,
typed State/Goal, full initial Inventory and any retained practice to the supplied
Lesson. Generic save validates bounded family metadata and the complete 2 MiB
Attempt; it has no catalog argument. Catalog-aware decode additionally checks the
authored context. Shared command text, authentic old script histories and legacy
scalar fields remain saved nonauthoritative data. No new historical record or
completion credential is created for NFS.

Every older direct prepare entry point rejects present NFS metadata before its
original mutation or early return. NAT and RPM memo presence guards run before
cache hits or snapshots. Other older specialized current helpers and generic
save/decode also reject a foreign NFS Session or Learning. These are narrow family
admission checks, with existing family validators and prepare bodies retained.
The reciprocal NFS classifier exhaustively rejects older typed metadata while
retaining historically shared fields and genuine run evidence.

NFS actions use one proposed State candidate. Borrowed streaming compact-JSON
substitution accounts for the actual complete Attempt (including authentic old
histories) before assigning State, Session or Learning. Preparation, separate
practice actions, Fill and practice Reset use the same cumulative 2 MiB frontier;
64 KiB Session/1 MiB Learning limits are not independently added to that cap.
Independent serde measurements cover workspace absence/presence and all optional
Session/Learning shapes. Escaped edit and same-action positive controls retain
all bytes on a rejected candidate. Global 2 MB pack and 16 MB progress limits
remain unchanged.

New attempts open Introduction; an existing attempt missing the new optional
metadata first opens Assignment. Present practice state and both independent raw
request drafts remain unchanged on reopening. Reset replaces only the selected
Attempt/practice as explicitly requested; backup inspection retains its existing
explicit shell re-evaluation behavior, which tests compare with an independent
old-only control. Plain load remains read-only. An ignored test requires the
retained actual evaluator9 capture and does not manufacture a replacement record.

The internal goal-aware `nfs ` JSON codec exists for fixed authored tests and
future native action routing. It is explicitly simulator-only, never presented
as a Linux utility or shell. A context-free dispatcher cannot perform mutations.
No result, Session display entry, checked bit, reference order or saved success
flag substitutes for a fresh current/saved/new-mount outcome vector. Faults remain
faults; no unsupported path can satisfy Expected::Denied.
