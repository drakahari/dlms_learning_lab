# Learning in DLMS Learning Lab

Open the installed application or the exact local candidate shown in
[Installation](INSTALLATION.md). Everything a lab does stays in the simulator.
Commands, scripts, files, networks and services in an assignment cannot change
your actual computer. The lessons work offline.

## Choose a starting point

Choose CCNA, LPIC-1, LPIC-2 or Bash/Shell, then a unit or topic. Use search to find
a skill; optional filters narrow difficulty, duration and progress. A lab card
shows its goal and estimated time before you start. Favorites keep useful labs
close; recent work and Continue return to saved attempts. Prerequisites recommend
preparation without locking experienced learners out of later work.

If networking is new, start with **Read an IPv4 address**. For Linux access, try
**Share a report safely**. For scripting, begin with the first Bash/Shell unit
and its introduction. You do not need a VM or an existing shell environment.

## Learn, try, then do the assignment

Learn mode opens a short **Introduction** explaining the tools and ideas you will
need. You can skip it and reopen it later. **Try example** uses separate values
and saved work. It lets you run a small example, make the suggested change and
see what happens. Example work does not complete the assignment or overwrite
its draft.

The assignment is the complete practical task. Read its goal, investigate the
supplied state and make the needed changes. Networking labs use configuration,
topologies or allocation tables. Linux investigation uses a simulated terminal.
Scripts and service configuration use editors. The controls vary with the work;
not every assignment uses the same tool.

Challenge mode keeps the meaningful assignment while withholding the walkthrough
by default. Optional help is available when you choose it. Hints and worked
explanations are there to help you reason, rather than requiring you to guess.

## Run, check and retry

Run executes a script or other supported operation in the bounded simulator.
Stop cancels a running operation where that workspace provides it. Some
configuration editors have a separate Save or Apply action: read its label to
distinguish a draft from the configuration being tested. Each lab discloses its
supported commands or syntax. Unsupported input reports a limitation.

Check configuration or Check work evaluates the current result. In scripting,
the whole run can fail even when the selected individual case passes. Inspect
the named failing cases and expected versus actual output. Syntax errors,
unsupported features and incorrect results need different repairs; the feedback
helps you choose what to change. Each behavior test uses its own sample inputs
and reset simulated files where relevant.

You can retry. A valid alternative can pass without reproducing the worked
answer. Breaking a successful configuration or editing a script can invalidate
current success. Recheck after changes. Completion records do not mean every
walkthrough step was clicked or that the whole certification objective is covered.

## Leave safely and return

Back to library keeps saved assignment work and separate example drafts. Continue
or reopening the same lab restores that attempt. Reset asks for confirmation and
starts that selected attempt again; it does not erase other labs. Cancel keeps
your work. A running operation may have its own cancellation behavior, described
in that workspace; a stopped run is not a completed assignment.

Settings → Your data provides **Export backup…** and **Restore backup…**. Keep an
export before moving machines or replacing an installation. Restore validates
the file, shows a preview and requires confirmation; it preserves a recovery
backup before replacing progress. See [Progress recovery](PROGRESS_RECOVERY.md)
for locations, limits, migration and recovery details. Earlier evaluator credit
can remain visible while a new run is needed to verify current behavior.

## Make the workspace comfortable

The toolbar's text-size and theme controls apply immediately and persist. At
large text sizes or narrow widths, scroll to reach the rest of a task; the app
does not shrink your chosen text to force a fit. Theme samples live in
Settings → Appearance and are examples, not lab actions. They do not change your
desktop theme. Tab normally moves between controls. In script editors, Tab
indents, Ctrl+Enter runs, and Esc releases editor focus so you can navigate other
controls. The editor shows these shortcuts below its input area.

These are authored practice scenarios within disclosed models. Full exam
coverage, real-equipment experience and certification outcomes are not promised.
Current coverage and remaining limitations are recorded in
[the objective map](OBJECTIVE_MAPPING.md).
