# Next shell capability: bounded indexed arrays

**Status: specified/reviewed, not implemented or taught.** Current evaluator5 still rejects arrays. This contract is the next capability checkpoint after the installed M40 candidate; no authored coverage or learner mastery is claimed here. No new dependency or external execution engine is proposed. Keep native/offline architecture, source/editor/examples/progress and bounded in-process evaluation.

Use a typed runtime value (scalar or dense indexed elements), not a joined string. First support Bash-specific standalone `name=(word...)`, empty `name=()`, constant canonical nonnegative decimal `${name[0]}` reads, sole quoted `"${name[@]}"`, and `${#name[@]}` count. Cap128 elements and charge bytes/slots before allocation, cloning or expansion. Evaluate the full compound right-hand side against prior bindings, then replace atomically. Existing supported splitting/globbing/quote provenance applies to compound elements; stored wildcard bytes remain protected when expanded through quoted @. Distinguish an unset variable, zero-element array and one empty element. Scalar @ has one element when set and none when unset.

Every ordinary variable operation must use shared typed accessors: plain assignment, read and for update element0 while retaining other array elements; ordinary `$name` reads element0. Existing `local name` retains an outer array's type with an empty local value, and return restores the whole shadowed typed value with current dynamic visibility. Include arithmetic, locale selectors, command-prefix restoration, pipeline copies and call-frame locals in this audit. Validate reserved base names so indexed syntax cannot bypass special-variable/IFS restrictions. Case.env remains scalar declarative input; no runtime variable state is currently serialized.

Parse compound assignment as its own bounded node, distinct from `name()` function syntax and unsupported groups/subshells. Permit brackets only inside recognized supported parameter forms; general bracket globs stay rejected. Canonical decimal indices mean0 or a nonzero digit followed by decimal digits. Reject leading-zero forms rather than silently treating Bash's octal010 as decimal10.

Initially reject computed/negative indices, explicit index writes, sparse/associative arrays, +=, unquoted/mixed/concatenated @ expansion, *, slices, indirection, unset, read -a and declaration attributes. Report honest unsupported diagnostics. Do not teach any excluded behavior as working. Later extensions need their own reviewed contracts.

Resource analysis must include element count/slot overhead, aggregate live values, loop/argument lists, local shadows and pipeline snapshots, plus existing instruction/output/expansion-work budgets and responsive Stop. Before dependent lessons: controlled disposable Bash comparisons for quotes, empty elements, scalar interaction, prior-binding expansion, loops/functions/local restoration, index boundaries, wildcard literals and diagnostic/limit cases; current behavior alternatives/negative tests and native editor/run/stop/resume. If semantics change, use evaluator6 and existing exact before-shell backup/history/current-only credit migration. No prior learner answers or array mastery may be invented.
