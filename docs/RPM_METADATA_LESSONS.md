# RPM metadata and mixed-content recovery

Two registered LPIC-1 activities follow package investigation and file access policy:

| Stable lab | Practical task |
|---|---|
| `lpic1-rpm-metadata-preserve` | Repair installed file attributes while retaining intentional site configuration text and unrelated packages. |
| `lpic1-rpm-mixed-recovery` | Combine metadata-only restoration with an exact-version reinstall for a damaged plain file; preserve local configuration and neighbors. |

Unit `rpm-payload-recovery` uses the approved Introduction → separate guided
practice → independent Assignment. The Introduction explains installed records,
local text versus attributes, exact versions and choosing the smallest repair.
The gallery example has different package names, paths and text. Its runnable
experiment damages one requirement and supplies a reasoned retry. Assignments
start with intentional drift; commands and answers remain optional help.

The existing native console and read-only inspector remain the workspace. The
inspector displays current payload text and metadata, distinct from the installed
record. `rpm --restore NAME` is a real RPM command within a newly disclosed,
source-authorized subset; the inspector is an explicitly native simulator tool.
No host package manager, filesystem or process executes a learner command.

Grading checks resulting version, individual metadata, retained local contents,
plain-file payload and neighbors. Success is recomputed after further repairs or
damage. A successful command is insufficient; a metadata-only repair cannot fix
damaged contents, and an offered newer version does not meet an exact-version task.
Alternate supported operation orders pass. No old lab requirement is changed.
