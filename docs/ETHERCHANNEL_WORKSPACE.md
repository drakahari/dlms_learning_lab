# Bounded L2 LACP application adapter and separate practice

Three authored L2 LACP assignments are integrated in Main164/42 after the exact
original154 definitions; their unit precedes the optional-input and recurring-job
units. Original specifications and unit objects remain preserved. The separate
technical fixture is unregistered and never curriculum credit. Main source/content
and behavior gates are distinct from actual native/candidate acceptance, whose
receipts are pending in CATALOG164_MILESTONE.md. See ETHERCHANNEL_SUBSET.md for
equipment boundaries. Current CCNA2.4 is narrowly Partial for L2 configuration/
verification only; L3, IOS and actual packet/timer behavior remain unmodeled.

## Actual outcomes and immutable context

The authored Definition owns its initial State. Runtime configuration may change,
but the entire supplied topology, capabilities, system identities and current cable
availability must match that origin. Catalog-aware preparation/current checks and
restore/decode pin source version, full initial State/Goal and any retained practice
to its exact Lesson Definition. No reference State, action counter, transcript,
selector or saved checked flag confers completion.

A BundlePair requires actual participating reciprocal physical pairs between the
intended local groups, a declared2..8 educational member minimum, and a bounded
allowed cable domain. One member can still be operationally Ready in the pure
model. This first adapter deliberately supports two-data-VLAN trunk assignments:
every BundlePair at Current or a named Fault source needs two distinct positive
VlanService anchors for that same unordered group pair at that same source. Query
minimums are2 through the pair's requested minimum, so current3/fault2 remains
expressible. Healthy-neighbor service, a swapped condition, unreferenced computed
cell or unsupported outcome cannot substitute for the target's service.

Current plus up to four nonempty forced-down cable conditions are calculated once
in the existing pure batch. Up to eight named service queries reuse those snapshots;
no trial configuration is installed. Duplicate/unknown/unused names, invalid member
domains and unsupported anchor relationships reject before computation. Additional
rows can require retired membership to be empty and preserve explicitly named
initial ports, groups or device VLAN databases. These scopes must be visible in
the visible assignment, never hidden whole-network solved-configuration matching.
Feedback distinguishes actual count/domain failures, excluded links, unsupported
partner selection, inactive VLAN, disallowed VLAN and changed protected settings.
Messages are bounded512-byte text; neither color nor a fabricated CLI status is
completion authority.

## Raw drafts and explicit application

A Draft has exact supplied device/port/group keysets. Admin/membership/mode/rate/
duplex/profile mode use typed values. Numeric profile text is at most8bytes,
comma-separated VLAN lists384bytes, and readonly selectors32bytes. The complete
encoded draft is limited64KiB. Partial malformed raw text remains editable.
Access mode parses only access VLAN; Trunk parses only native and allowed values.
Inactive raw fields remain saved and do not block a matching active profile.
An empty active device VLAN database is a real supported misconfiguration; an
empty trunk allowed-list fails the disclosed pure schema. Admin-down and absent
membership do not bypass the active profile's input validity.

Set-draft helpers admit the borrowed whole proposed draft/learning/Attempt before
copying it. Apply parses every active field into one bounded configuration,
validates context/action/core State and complete proposed Attempt, then consumes
that candidate in one reconfigure commit. A late error retains the complete caller.
Pending active edits invalidate current success without changing applied state;
readonly selectors and ignored inactive raw values do not. Every successful Apply
must mark the eventual UI dirty even when its notice or draft bytes are unchanged.

The sim-lacp JSON bridge exists only for fixed authoring/tests and goal-aware engine
validation. It is not IOS and must not appear as learner command instruction.
Context-free engine mutations reject. No host executable, process, packet, service,
filesystem or network operation exists on this path.

## Separate teaching and progress

Lesson provides prerequisites, up to six short concepts, an independent example,
worked typed Configure actions, an adverse experiment with a literal complete
expected vector, and repair actions. Authoring validation replays only these
bounded supplied plans and verifies reachability. Current grading does not replay
them. Assignment and gallery topology/device/group/cable/MAC identities are
separate; the technical contexts also have different namespaces from each other.

Learning owns its actual evolving example State and raw Draft independently of
the assignment. Fill populates the selected worked configuration's practice draft
only. It does not Apply or complete anything. Apply practice publishes only that
example's draft. Reset example replaces only its own practice and opens Example.
New preparation opens Introduction; a legacy attempt without prior teaching opens
Assignment, and valid retained view/drafts survive repeated preparation. Challenge
keeps the same assignment and hides unsolicited teaching in the native workspace.

Optional etherchannel_draft/etherchannel_learning fields omit None; the optional
Scenario teaching field does too. Earlier wire representations and real histories
are preserved. Foreign typed metadata rejects reciprocally across all old families,
including NFS/RPM, before old prepare mutation and old memo hits/copies. Common
commands/scalars and genuine script histories remain retained nonauthoritative
information. Existing backups use the same validation paths; no migration invents
answers or credits for new requirements.

## Authored unit and coverage boundary

1. `ccna-lacp-initiation`: two passive pairs must form a two-member data trunk;
   either active end or both ends are accepted; preserve operations links.
2. `ccna-lacp-member-service`: repair a local profile mismatch, then independently
   restore the missing second VLAN across the same intended group pair.
3. `ccna-lacp-resilient-handover`: clear previous membership, configure at least
   three pairs, prove both VLANs retain two pairs in each supplied one-cable loss,
   and preserve a working neighboring group. A valid four-pair alternative passes.

The first lab requires the existing VLAN-trunk lab; the later labs build on their
predecessor. Each has distinct ungraded example identities/values, a reversible
adverse experiment and authored explanations. Literal initial/wrong/partial/
post-pass-break vectors and two alternate plans are supplied independently of
runtime outputs in the content-review fixture. Registration and narrowly scoped
2.4 L2 Partial evidence do not complete technical/native acceptance. No Layer3,
IOS command-syntax, negotiation timing or whole-objective coverage is claimed.
