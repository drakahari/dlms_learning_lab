## Taught distinctions and alternatives

A local address identifies an inside device; a static global exists when its
translation rules are applied and supports reversal before outbound. Applying
rules never creates a dynamic map. Outbound can allocate/reuse one; Reverse only
observes an existing map. Check reads current maps and tries new sample requests
without changing the workspace's holdings.

Dynamic capacity here is the **total number of dynamic address slots after static
reservations**. A currently held dynamic global still counts as a usable policy
slot. The goal does not require two additional unallocated globals after the two
active clients already hold maps. Static reservations inside a pool reduce that
capacity. Prefixes select supplied addresses; /31 and /32 selection are not
interface usable-host-range exercises.

Static repair accepts minimal in-place correction or incremental remove/re-add
while preserving the named observer. The pool task accepts a /30, exact-pair /31
or a different valid block excluding guest, with different supplied ranges; its
second alternative also inspects beta first. Handover accepts different eligible
prefixes/pools and either active request order. A retired device's former global
may be reused by another allowed identity. The goals preserve named outcomes,
not one hidden whole-configuration whitelist.
