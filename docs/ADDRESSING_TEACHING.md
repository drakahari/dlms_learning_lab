## Authoring and progress boundary

`Scenario.address_teaching` is optional declarative data for `Subnet` and `Vlsm` only. It supplies a prerequisite note, short named concepts, a distinct example description/fixture, reference state changes and a concrete experiment. It does not add executable scripts. Reference `answer`/`allocate` adapters are internal validation data; learners use native fields/tables and never see these as purported terminal commands. Every fixture starts unsolved and its references must reach current goals. New subnet fixtures include the second workstation. Text, reference length, row counts and team names (80 bytes) are bounded.

A distinct subnet example needs a different IP or prefix. A distinct VLSM example needs a different pool/prefix or host-count multiset; renaming/reordering labels is not a separate problem. Resume/import pins the example IP/prefix or ordered pool/team/host requirements. Original assignment inputs are also pinned to the authored scenario; answers and allocation text remain editable. A legacy absent second-workstation field is still accepted and migrated by the existing explicit legacy-credit rules, without inventing an answer. Rejected data leaves original file bytes intact.

`WorkspaceData.address_learning` is omitted on older profiles and prepared lazily. New attempts open Introduction, existing attempts open their saved assignment. Example state and its exact checked snapshot are separate from assignment state and existing numerical practice. Checking/filling/resetting an example cannot award assignment credit. Changed answers suppress current example success. Example/assignment/numerical editor IDs have distinct namespaces so native undo history cannot cross those boundaries. Learn can skip/reopen teaching; Challenge retains the whole assignment and requests help explicitly.

The small block visual derives its changing octet from the prefix. Its block size counts values in that octet; later octets contribute another factor of 256 each. It never labels a /23 block as only two addresses. Bounded grid tiles wrap by whole cards rather than squeezing words into vertical text. The optional binary explanation uses bit weights and keeps address values separate from mask selectors.
