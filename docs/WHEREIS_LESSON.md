## What the learner does

A supplied binary already works. Its correctly named manual is missing, and its
published source has the wrong release. The learner investigates three independent
categories, reads the release note, compares staged/published/archive contents,
publishes the approved support files and retires only the named old manual.
The binary, neighboring audit files, archive, stage, private notes and metadata
must remain intact. A found pathname with obsolete contents is a meaningful wrong
answer. Optional named scratch work must be gone at handover.

Introduction explains each category and the literal flag pattern before practice:
small `-b/-m/-s` chooses binary/manual/source; capital `-B/-M/-S` supplies its folder;
`-f` ends the folder list before the known program name. A bare `NAME:` output
means no matching name; the normal query still exits successfully. `which` checks
external-command eligibility in the supplied PATH; `whereis` names artifacts.
Neither runs the supplied program here. Naming a file proves neither its release
nor its execute/read permissions.

Eight worked commands use a different gallery, program and release. The separate
practice terminal keeps actual output below the input and offers explicit Insert
command/Run actions. An archive-copy experiment demonstrates that source discovery
still finds the path after its contents become wrong, followed by a repair.
Assignment requirements retain the complete handover; no repair commands or
expected contents are populated by default. Challenge keeps the same meaningful
task and hides unsolicited guidance. Long worked commands wrap; old lesson layouts
retain their appearance. All controls use the existing native alignment helpers.

## Model and authoring

`filesystem::whereis_deployment::Definition` holds trusted initial/expected trees,
a bounded whereis query context, up to four editable ordinary-file slots and the
selected category outcomes. It protects every PATH folder, directories, binaries,
caller/groups/home/mask and all unrelated paths, bytes, owners/groups/modes. A
candidate mutation is published only after pre/post policy checks. Queries borrow
actual virtual directory state; they do not recognize a solution command string.
The complete resulting tree and category selections determine success, independent
of command history, exact repair syntax or walkthrough position. Multiple literal
copy/move/relative-path methods are supported; wrong archive text, partial work or
excess permission changes fail. Cwd and modification bookkeeping are not mastery.

A small borrowed `discovery_policy::Reference` selects the original modes-only
policy or the new deployment policy. The old mode policy and
`Tree::execute_in_context` body remain unchanged. Source-free marked trees refuse;
engine, pack, example, feedback and catalog-aware persistence pair against the
held author source. Duplicate, missing, mixed and crossed references refuse before
legacy fallback. Initial/example identities, names and search folders differ.
No expected definition or authored solution is inserted into saved learner work.
No Tree wire field, progress schema, shell evaluator or dependency changes.

Pack admission explicitly checks initial/source pairing and the taught solution’s
reachability. Constructors, rendering, reset and loading do not execute solutions.
Catalog-aware save/load preserves both command drafts, example state, favorites and
other attempts. Restore rejects erased/crossed context before replacing good bytes.
See [WHEREIS_SUBSET.md](WHEREIS_SUBSET.md) for exact utility limits/reference scope.
