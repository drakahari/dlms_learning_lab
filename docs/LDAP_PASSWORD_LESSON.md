## What the learner does

Introduction explains required connection protection, the supplied virtual CA
settings, and the three independent bind/old-target/replacement prompt roles.
Four worked rows use a separate training person and directory. Try example
repairs an unprotected request, runs it, and inspects actual new/old/unrelated
login results before checking three sample cases. Optional Fill worked example
populates only that practice draft without running or earning assignment credit.

The independent task repairs settings and command/prompt choices for the named
person. Three policy/credential samples require the requested replacement to
work, the previous credential to fail, and every unrelated identity and complete
directory data to remain intact. The supplied settings and prompt mistakes are
intentional. Challenge keeps the full task and hides unsolicited worked guidance.

Command success is not mastery: setting the previous password again can exit0
while fresh-login tests correctly fail the assignment. Omitting the old-target
prompt can pass two samples while failing the sample that requires it. One
shared fictional value can make a different bind profile pass one sample;
individual passing results are preserved while overall success remains false.
Equivalent supported command ordering, optional self DN, successful -Z, omitted
default TLS_REQCERT and hard alias are accepted by behavior rather than strings.

## Interaction and persistence

Native configuration editor, command field and three fictional-profile pickers
use existing font-derived controls, optional help and separate learning screens.
Actual output and Expected/Actual login observations are distinct from unchecked
work and all-case grades. Wide columns stack at enlarged text or narrow windows.
Any draft edit clears prior output/current checks. Practice, assignment and the
selected sample persist independently; reset affects only the chosen attempt.
Saved data contains profile keys, never supplied sample passwords or proof objects.
Fresh checks rebuild source-held state; imported success flags are not trusted.

## Boundaries and evidence

All TLS, names, issuers, time and trust roots are symbolic source facts. There is
no real TLS handshake, cryptography, certificate parsing, network, host file,
credential store or system service. Only bounded supported settings and literal
ldappasswd syntax are evaluated; unsupported real-client behavior is disclosed.
Plaintext fallback is outside this protected subset, not claimed impossible in
real OpenLDAP. See [the explicit subset](LDAP_PROTECTED_AUTH_SUBSET.md).
