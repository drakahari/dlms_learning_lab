## Deliberately bounded semantics

`src/host_direct_dns.rs` parses these real dig forms, case-insensitive A/name:

```text
dig @SERVER NAME. A +short
dig +short @SERVER NAME. A
dig @SERVER NAME. -t A +short
dig +short @SERVER NAME. -t A
```

One canonical numeric IPv4 server, absolute supplied .lab.test name, positive A
record and terse output. Each exercise explicitly enables one or two resolvers
already present in its typed world. Lookup bypasses configured nameservers/NSS;
it checks the current virtual IP path and derives the selected server's actual
record. Edits to that record in fixed model tests change the observed answer.
The positive answer prints its IPv4 stdout, then a clearly marked simulator note
with server/name and modeled command status0. This does not alter client settings.

The supplied flat A snapshots do not establish negative DNS response metadata,
TTL, alias chains, recursion or transport. Unknown names/types/options/servers are
honestly unsupported: absence is **not** inferred NXDOMAIN or NODATA. An unavailable
virtual route gives a labeled path observation; no real timeout or utility status
is invented. Header/TTL output, default query type, implicit/named servers, search,
DNSSEC, cache, retries, other options, host and general BIND behavior stay open.
No host dig process, resolver, file, packet, clock or network fallback exists.
512-byte commands, bounded source resolvers/records and existing24×4096-byte
terminal history apply. Unknown/escaped/shell inputs cannot leave the model.
