# Bounded command substitution — evaluator 7

This document describes the isolated revision7 implementation. M1 parser, M2 preparation and M3 cooperative runtime passed independent source review. M4 public execution, migration/restore and native acceptance remain under review before main integration. No new lesson, dependency, host execution or coverage promotion is included. The separate terminal remains literal-only.

The implementing agent selected the cooperative internal approach under existing application/engine authorization. This is not an explicit owner selection of that option. The public application/runtime architecture is unchanged: one in-process Rust VM executes synthetic input against a virtual filesystem.

## Supported syntax and data

Only original-source `$(LIST)` nodes execute. LIST uses the existing documented VM grammar: supported assignments, indexed lists, functions, if/for/while lists, simple pipelines, redirections and nested dollar-parenthesis captures. The parser compiles main and child bodies into one immutable instruction arena, with stable function/jump targets. Empty or comment-only bodies produce empty output and status zero. Arithmetic expansion inside a body remains supported; a capture inside an arithmetic expression does not.

Results work in ordinary arguments, assignment-only values, literal `local` declarations, dense list assignment, for-list words and supported redirection targets. Generated builtin/function command heads are prepared exactly once. A generated name can select only an existing supported builtin or available function; it never causes host lookup or source re-parsing. Existing restrictions on assignment prefixes, function calls inside pipelines, whole-function redirection, declaration names, computed indices, parameter operators and unmodeled variables still apply.

The child inherits visible variables/lists, positional arguments, function bindings, status and input/output bindings. Variable/list/function-definition/shift/local changes stay in the child; virtual file effects and consumption of the inherited input cursor remain visible to the parent. A function actually called inside the child may use supported local/return, including an inherited function. A direct child-top-level local/return is unsupported, even when a parent function is active. Child call state never unwinds a parent call. `exit N` completes only the child scope.

The replacement is stdout alone, with **all trailing LF bytes removed**. Leading/interior LF, spaces, tabs, CR and UTF-8 remain. A double-quoted empty value retains one field; a bare empty value may disappear. Quote provenance survives adjacency to other word parts. Bare output uses fixed default-whitespace splitting and the existing virtual-file `*`/`?` glob subset; double quoting suppresses these. Emitted quotes, dollar signs, operators and substitution-looking text are data, never re-lexed or expanded again.

## Expansion, redirection and status order

All parameter/arithmetic/substitution parts across a command's argument list are prepared before splitting/globbing that list. Thus an earlier `*.txt` argument can see a virtual file created by a later argument capture. Ordinary assignment-only RHS values publish sequentially. Literal local RHS words all finish expansion before declaration mutation. Sole quoted positional/list expansions retain their existing field behavior.

Argument substitutions precede outer redirections. Each redirection target instead expands immediately before applying that redirection, from left to right. Earlier input/error/output bindings are therefore visible to a later target capture. `: 2>errors.txt >"$(printf warn >&2; printf out.txt)"` writes warn to errors.txt; reversing the redirections leaves warn on the original stderr. An earlier input redirect supplies the later target capture's input cursor. A missing earlier input stops later target captures/file effects. Redirection words are never all pre-expanded. Descriptor copies retain the sink selected at that point; inner descriptor order matters too.

A completed capture updates the expansion-time status used by later `$?` parts of the same command. An ordinary builtin/function then supplies its own final status. With no command name, assignment/list/redirection-only commands use the last executed capture status, or zero when none ran; a redirect failure takes precedence. Successful literal local declarations supply status zero. An ordinary child nonzero status such as false/exit7 is distinct from an evaluator failure.

Unknown commands, unsupported syntax, resource limits and Stop fail the entire case. Bounded simulator diagnostics/status2 are intentional; exact Bash fatal diagnostic text is not reproduced. Earlier virtual file/stream effects may remain visible in an ungraded error outcome; the pending parent command never resumes after fatal failure or Stop.

## Cooperative execution and ownership

One Vm owns files, code, root counters and sink buffers. A typed request suspends the exact word/part/redirect/pipeline stage. The parent context moves into a bounded frame; child environment/list/argument/function snapshots clone only after their combined copy peak is checked. The child runs through the same public ticks, then injects typed data into the waiting part. No synchronous child VM or hidden run-to-completion loop is used by expansion.

Each tick executes at most min(requested,64) semantic instructions and32 additional preparation units across all descendants. A unit handles one part/word/redirect/stage transition or bounded builtin. Stop discards the whole frame tree, pending data and sinks and cannot resume. Backup preview cancellation checks between ticks and drops the whole VM; a deterministic worker test cancels after a child loop has started, without returning a graded candidate.

The active finite input binding has one physical text/cursor owner at the execution frontier. Inherited reads advance that cursor through descendants. Explicit redirects create separately bounded snapshots and restore the inherited binding on return/exit. Ordinary input and redirected-while sources are guarded across all active/suspended scopes: writing/truncating a currently active source is unsupported before the matching write and parent builtin. Superseded ordinary bindings cease to be guarded. This is a finite-snapshot subset, not mutable-file-descriptor conformance.

A root buffer arena holds at most17 live pipeline/capture sinks, from8 captures plus their pipelines and the root pipeline. Slots are reused. Moving buffer→pipeline→sink relinquishes old logical output ownership before append; simultaneous physical copies remain charged to memory. Raw stdout is checked before LF trimming, so newline-only output cannot evade output/work limits. Trimming/copy processing is charged before retention.

## Bounds

The whole root run shares source16KiB,4096 aggregate tokens,24 syntax nesting levels,128 compiled capture sites,8 lexical/active capture levels,128 fields/arguments per prepared list,64 redirects,16 pipeline stages,64 function names,32 actual active calls across all frames,256 live variable names,64 virtual files,256KiB live virtual text,32KiB retained/intermediate output,2,000 instructions and1,000,000 expansion-work bytes. Recursion through one capture site does not evade active depth8. A child never receives fresh counters or extra calls/files/names.

The live-text ledger includes root streams, owned program text once, virtual files, active/suspended contexts, prepared fragments/fields/declarations, known String/Part slots, saved input, descriptor paths, pipeline/capture buffers and explicit scratch. Actual simultaneous environment/list/source/merge/split/glob copies reserve workspace first. Moving ownership transfers its charge. Immutable program text and suspended contexts have cached sizes because they cannot change while suspended. Name unions include unset ancestor locals and inherited function bindings. Same-name inheritance does not grant extra names; copied payload still consumes memory.

This ledger models initialized virtual payload/known slots, not allocator spare capacity, B-tree overhead or OS RSS. Parser/control structures have separate fixed shape bounds. The bounded diagnostic has its existing separate ceiling. Variable/list reads borrow stored text; prepared function arguments move. Bare runs of default-IFS whitespace compact to one delimiter after full work charging. Per-expansion bounds remain, but aggregate pending/copy peaks can fail first.

## Deliberate exclusions

Backticks; process substitution; standalone parenthesized subshell/group commands; heredocs/here-strings; jobs/background concurrency; aliases; eval/exec/source; traps; export/set/shopt/options including errexit/inherit_errexit/pipefail; Bash5.3 `${ command; }` / `${| command; }` alternatives; binary/NUL data; arbitrary executables; and all previously unsupported VM grammar/utilities remain excluded. Single-quoted or escaped `$(` remains literal. The separate terminal rejects typed substitution nodes before dispatch.

Bash's input-only `$(<file)` shorthand is excluded. The parser classifies its exact AST: one no-name command with exactly one input redirect, even with trailing semicolons/comments/newlines. Generic execution would incorrectly produce empty output instead of Bash's file content. A second redirect makes an ordinary redirection-only body and is not over-rejected. Supported simulated `cat PATH` can capture virtual file content. Captures in arithmetic expressions, inherited-direct local/return and unsupported patterns receive honest diagnostics rather than approximated output.
