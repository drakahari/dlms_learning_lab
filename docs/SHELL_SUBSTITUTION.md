## Reviewed M2 preparation checkpoint (captures still gated)

Typed tick-owned continuations separate ordinary arguments, assignment-only RHS/store, literal local declarations, array and for-list words, while-file input, and each redirection target. Source parts evaluate once across a complete argument list before fields and globs are resolved. Sole quoted positional/array lists keep their existing field semantics. Prepared output is data and is never re-lexed or parameter-expanded again. Long runs of bare default-IFS whitespace are represented by one delimiter before retention, with work charged for the full original text; fields/globs still wait for the whole list.

A pipeline continuation retains its stage/environment/input state and resolves each prepared command head once. Supported function calls consume those same prepared arguments. Unsupported function/local/return pipeline contexts are checked when their stage is prepared; there is no speculative evaluation of later stage heads. Ordinary assignment RHS values are published sequentially; all literal-local RHS words finish preparation before declaration mutation. Redirections expand and apply left to right. An input redirect binds its cursor immediately for later target preparation, and a missing input stops later target/file effects. Caller input is restored after the command, respecting function-return/while-input unwinding.

Each public tick still permits at most64 semantic instructions (or its smaller requested budget) and at most32 additional preparation units. A unit processes one source part, one prepared word, one redirect, one stage transition or one bounded builtin. Stop discards pending preparation; a later tick cannot execute its suspended command. M2 did not add a synchronous child VM. M3 reuses these exact suspension points for root-owned child frames; shared descendant behavior is exercised only through a private cfg(test) constructor while the public gate stays closed. The existing per-list128-field/256KiB and cumulative expansion-work guards remain active.

## Reviewed M2 resource and input fixes (isolated)

It includes source-word copies and Part slots, evaluated fragments, ready/returned String-field slots, prepared arguments/declarations, saved command input, pipeline snapshots and output, plus existing environments/arrays/local shadows/input/files. Short-lived source character/key buffers, expanded text, split fields and quote masks reserve workspace before copying/appending. The logical quote mask charges one byte per UTF-8 byte; String and Part slots use their Rust sizes. Shared immutable compiled code has separate16KiB/4096-token/parser bounds and is not duplicated into a child VM. M3 now counts its owned text once and includes descendant frames and live capture sinks as described below.

Variable/array reads borrow stored text while building a prepared fragment. Simple fragments and prepared function arguments move into their next owner; joining quoted fragments preflights the temporarily coexisting appended source. Large bare-whitespace runs are copied into a compact delimiter allocation, freeing the large raw allocation after its fully charged processing. Split/glob input and output coexist under the root ceiling; moving completed fields is a separate bounded preparation step. Accounting models initialized virtual payload/known slots and explicit scratch, not allocator spare capacity, B-tree node overhead or operating-system RSS. ## M3 cooperative runtime (private tests, not activated)

One Vm owns instructions/work, the virtual files, immutable program, input identity sequence and all output sinks. A typed body request suspends the exact M2 word/part/redirect/stage. The parent context moves into a bounded suspended frame; visible environment/arrays/args/function-name bindings clone only after their combined copy peak is checked. Child call state starts empty. A function actually entered inside the child may use local/return; a direct child-top-level local/return remains unsupported. All function targets still address the same immutable arena. Child exit completes its scope; unsupported/resource errors and Stop fail the entire run.

The current finite input binding stays physically owned once at the active execution frontier. Its identity/cursor move through suspended contexts; inherited reads advance it, while explicit child redirects get separate finite snapshots and restore the inherited identity before completion. Return/exit unwind redirected while inputs correctly. Root write guards inspect suspended ancestor while inputs and all active ordinary input scopes. File effects share one root map and survive as partial effects in an ungraded runtime failure.

Root buffer IDs identify pipeline-stage and capture sinks; descriptor copies retain the sink chosen at that point. A maximum17 simultaneously active buffers follows from8 captures plus their pipelines and the root pipeline; completed slots are reused. Earlier redirected stderr/stdin therefore bind later target captures, while argument captures precede the outer redirects. Output text is injected into a waiting typed data part, with its original quote provenance; it is never re-lexed. Completion status becomes visible to later outer expansions and the last-substitution latch for assignment/array/no-name purposes. Normal commands and literal local retain their own final status.

The256KiB virtual-text ledger includes root stdout/stderr, one shared program-text payload, files, active and suspended contexts, prepared values/known slots, pipeline/capture buffers, descriptor paths and explicit copy scratch. Program control metadata, bounded parser/control structures and allocator spare capacity are separately bounded rather than represented as OS RSS. Immutable program text and suspended context sizes are measured once and cached; suspended contexts cannot mutate until restored. Shared aliases do not duplicate sink/input payload in the accounting. Actual simultaneous copies are checked before allocation; moving already owned payload transfers its charge. The diagnostic itself has its separate existing bounded length.

The32KiB output ceiling covers root streams and all retained capture/pipeline output owners across the frame tree. Buffer→pipeline→sink transfers relinquish the prior output ownership before appending, while the physical source-copy workspace remains charged to virtual text. Completed capture data or consumed pipeline input becomes ordinary prepared/input data and remains in the256KiB ledger. Raw stdout is checked before removing **all** final LF bytes; a trimmed value is copied only when needed to release the raw allocation, with raw processing/copy work charged before the move. Prior parent streams and still-live ancestor capture sinks retain their output charge throughout nested work.

The root2,000-instruction and1,000,000-byte expansion-work counters never reset on child entry. Calls sum across all frames, with32 actual active calls total. Variable names, including unset parent locals, have one256-name live union; function names have one64-name live union; inherited same-name bindings are not fresh allowances, while their actual copied strings still count as memory. The64-file ceiling belongs to the root map. Active captures are bounded by8 even when recursion repeatedly invokes one compiled site. The compiler still separately enforces128 sites,8 lexical capture levels,4096 aggregate tokens and24 syntax levels.

## Recommended first complete slice

The implementing agent selected this internal approach under the owner’s existing application/engine authorization; its bounded design and parser foundation passed independent review. The agent-selected scope, 2026-10-23, uses the cooperative native-frame design, with no dependency/public-API/runtime architecture change; it is not an explicit owner selection or approval of this option. Exclude substitution inside arithmetic, `$(< file)`, and direct `local`/`return` inherited merely from an enclosing parent function. Keep inherited function calls and functions defined/called inside a child; their own active call frames may use supported local/return. Include outer pipeline stages and generated builtin/function heads with exactly-once preparation. The later runtime implementation still needs independent review and the fidelity, budget and migration gates below.

Support only the standard `$(LIST)` form, as an original-source expansion node. LIST uses the already documented native shell grammar and in-process commands, subject to the limits below. Existing unsupported constructs stay unsupported inside it. This includes finite/limited if/for/while lists, supported simple pipelines, ordinary assignments and arrays, supported function definitions/calls, existing redirections and nested dollar-parenthesis substitutions. Empty or comment-only bodies produce an empty value and status zero. Arithmetic expansion inside the body remains available. Command substitution *inside an arithmetic expression* is explicitly excluded from this slice; the parser rejects it rather than evaluating a child from an arithmetic callback.

The caller may use the result in quoted or unquoted ordinary arguments, assignment-only values, existing literal `local` declaration values, dense array-assignment words, for-list words, and supported redirection words. Resolve expanded command heads once: a result can name a documented builtin or available function, but can never trigger host lookup or source re-parsing. Existing restrictions on assignment prefixes, function calls in a pipeline, whole-function redirection, special declaration-command names, computed array indices, parameter operators and unmodeled variables remain in force. A substitution in an outer pipeline stage must use the same resumable command preparation as other contexts; do not pre-execute it to inspect the command head.

Execution and expansion rules:

1. Execute LIST in an isolated shell-environment frame. Inherit visible ordinary variables/arrays, positional arguments, existing functions, current status and the inherited finite input/output bindings. Variable, array, function-definition, shift and local changes stay inside that child. The parent can still see virtual file writes and consumption of an inherited input cursor. A child’s explicit input redirection must not consume the parent’s inherited input. Active while-input write guards remain effective through child frames.
2. Replace the source node with its stdout only. Remove **all final LF bytes**, and no other trailing character. Preserve leading/interior LF, spaces, tabs, CR and UTF-8. A quoted empty value remains one field; a bare empty value can disappear. Do not re-lex output: quotes, dollar signs, semicolons and nested-looking text emitted by the child are data.
3. Outer double quoting suppresses field splitting and filename expansion for the result, while preserving the existing per-byte quote provenance when it is adjacent to other parts. Bare results use the current fixed default whitespace splitting and the existing `*`/`?` virtual-file glob subset. Unsupported bracket/directory/recursive patterns still fail honestly. Assignment/declaration contexts retain their existing no-splitting rules.
4. Within a simple command, perform its parameter/arithmetic/substitution expansions in the observed Bash order, then split and glob the prepared argument words. Do not finish globbing each word before later words’ substitutions run. A controlled probe shows that an earlier `*.txt` sees a file created by a later argument substitution. The prior evaluator performed per-word expansion/splitting/globbing. M2 introduces a command-level preparation phase; capture execution remains gated while that refactor is validated.
5. A completed substitution updates the expansion-time status used by **later `$?` expansions in the same outer command**. The executing ordinary builtin/function then supplies the outer command’s final status. With no command name, use the last executed substitution status, or zero when none ran; a redirection failure takes precedence. This applies to ordinary assignment-only commands, dense array assignment and redirection-only commands. A successful `local` declaration still returns its own status zero, even when its value came from a failed child. Do not confuse a nonzero child status with an evaluator error.
6. Child stderr follows the caller’s currently active error binding and is not included in the replacement unless an inner descriptor copy directs it to the captured stdout. **Argument** substitutions precede the outer command's redirections. Redirection-target substitutions instead run immediately before applying their own redirection, using the bindings already established by earlier redirections. Thus `: 2>errors.txt >"$(printf warn >&2; printf out.txt)"` sends the warning to errors.txt; reversing those redirections leaves it on the original stderr. An earlier input redirect supplies stdin to a later target substitution and its consumed cursor to the executing builtin. An earlier missing input stops the redirect list before later captures/file effects. Never pre-expand all redirection words. Inner descriptor order matters too. All file effects stay in the virtual map.
7. `exit N` ends only the child capture. Bash permits direct local/return within a substitution when an enclosing parent function supplies the context, but the selected first slice explicitly rejects those forms with an unsupported diagnostic. A function entered inside the child, whether inherited or defined there, uses its own normal local/return rules. Child call state must never unwind or mutate a live parent call.
8. Unknown commands, unsupported syntax, resource limits and Stop remain evaluator failures for the entire case, even if an outer command could otherwise return zero. Ordinary child failure such as `false` or `exit 7` is data/status behavior and can be handled by existing control flow. Diagnostics stay bounded and simulator-specific.

## Deliberate exclusions

Backticks; process substitution; standalone parenthesized subshell/group commands; heredocs/here-strings; background/concurrent jobs; aliases; eval/exec/source; traps; export/set/shopt/options including errexit/inherit_errexit/pipefail; arbitrary executable lookup; binary/NUL data; and all existing unsupported grammar/utilities remain excluded. Single-quoted or escaped `$(` is literal, not an execution request.

Also exclude Bash’s `$(< file)` input-only shorthand initially. Bash captures file contents for that specific form, whereas running the current generic redirection-only VM command would produce no stdout; accepting it as an empty result would be wrong. Classify the parsed body, not its raw spelling: one no-name command with exactly one input redirect is still the shorthand with trailing semicolons, comments or newlines. A second redirect, including another `<` or `2>`, makes it an ordinary empty-output redirection-only body; do not over-reject those. Detect the exact excluded AST shape before execution. Use the already documented simulated `cat PATH` body when file capture is later exercised; the development probes here intentionally run builtins only. Ordinary supported redirection-only commands retain their observed status rules.

Bash 5.3’s `${ command; }` and `${| command; }` alternatives are out of scope: they have current-environment/REPLY semantics different from `$()`. Parameter fallback operators and computed array indices must not become accidentally supported just because they contain a substitution-looking sequence. Reject command substitution within `$((...))` in the first slice unless the arithmetic continuation design is accepted separately. The Bash reference fixture demonstrates its real numeric/status result, without promising support.

## Proposed bounds and Stop contract

Keep existing root-case ceilings: source16KiB, aggregate4096 tokens, syntax nesting24, 128 expanded fields/arguments,64 redirects,16 pipeline stages,64 functions,32 actual active function calls **summed across the whole parent/child frame tree**,256 variable names,64 virtual files,256KiB live virtual text,32KiB retained/intermediate capture and2,000 VM instructions; cumulative expansion work stays1,000,000 bytes. Capturing within an active parent function cannot grant32 additional child calls. Add explicit maximum8 active command-substitution frames and128 substitution sites in one compiled source. Count child syntax toward the aggregate token/nesting budget. The parser already enforces8 nested capture bodies,128 sites,4096 aggregate tokens and24 aggregate syntax levels. The private M3 driver also enforces aggregate frame calls and descendant live memory/output; these are not public capture guarantees while the constructor gate remains.

Budgets must belong to the root run. A child does not receive fresh steps, work, output or memory allowances. Count environment/array/argument/local snapshots, suspended command fields, input snapshots, pipeline buffers and active capture bytes before cloning/appending. Shared program and file storage are counted once; real simultaneous copies are counted separately. Capture raw stdout before LF trimming, so a large newline-only result cannot bypass output/work limits. Charge copying and trimming/replacement processing against expansion work. A completed capture transferred into prepared word data belongs to the live text budget; simultaneous capture buffers plus parent result streams remain subject to the shared output bound. The exact byte-accounting choices need implementation tests and must be documented rather than hidden as per-child resets.

Root `Vm::tick(n)` must charge descendant execution against the same instruction slice. It may suspend with a child loop/function active and resume the precise expansion continuation later. Stop and backup-worker cancellation must terminate the whole active frame tree, mark the case ungraded, and never resume a pending parent builtin. No `while !child.done() { child.tick(...) }` hidden inside one parent expansion is acceptable for the complete slice. This differs from the current bounded single-command pipeline operation: a substitution body can contain an arbitrarily repeating loop or recursion.
