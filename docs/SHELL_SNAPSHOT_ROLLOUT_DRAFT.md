## Teaching before assessment

The prerequisite path includes quoted command capture, helper arguments/returns,
immediate `$?`, IFS-empty `read -r`, dense whole-list replacement, loop/conditional
status and the two literal-interface projects. The introduction repeats the
needed boundary facts in six short concepts. It does not assume a new utility.

The key prerequisite is visible in Introduction: a plain command capture removes
all trailing LF. Each successful file read therefore appends the same fixed
nonLF marker *inside* the capture. The final character is no longer LF; all
original LF bytes survive. Comparing two marked values is injective even when
the marker itself occurs in data. The marker is not a forbidden input character
and never enters a report or file. The checked helper must not let a later printf
hide a failed cat.

The alternative using read reconstructs a value differently. A successful
`IFS= read -r` assigns a line without its LF and returns0. A last unterminated
fragment is still assigned but returns1; empty EOF assigns empty and returns1.
The helper appends one LF only for each successful complete line, then appends
the final assigned fragment and marker. Spaces, tabs, CR, backslashes and valid
UTF8 data remain literal. This is not a word-count or first-line comparison.

Each assignment has a smaller isolated runnable example with unrelated paths.
Iris/lily differ only by one final LF; removing the marker makes them falsely
equal, and restoring it repairs the example. Plum/dusk demonstrate one changed
target and old-current rollback; comparing plum with itself deliberately skips
the change, and restoring dusk repairs it. Example results remain separate from
the empty full assignment editor and cannot award assignment credit. Challenge
keeps the independent task and optional help; no wizard or unsolicited full
assignment is introduced.

## Bounded interface and policy

This is exact comparison of bounded valid UTF8/nonNUL model text, not arbitrary
binary cmp conformance. Task filenames follow an explicitly taught ASCII
business interface: first lowercase letter, then lowercase/digit/dot/hyphen,
1–12 characters total. Files themselves may contain arbitrary supported text.
An LF inside an argument is rejected as one invalid name, not treated as two
valid names. Same-path comparison is valid in the read-only task.

A rollout accepts `preview` or `apply`, a plan name and report name. The plan has
0–8 physical records, each `desired|current|rollback`. The final record may omit
LF. Eight is a small stated job bound under existing interpreter budgets, not a
raised language/resource cap. Every path across the whole plan is unique and
distinct from plan, report and protected `keep.txt`. Desired and current inputs
must exist; rollback may exist or be absent. The entire row grammar is validated
before cut extracts fields, so command capture never normalizes a filename.

Interface/mode errors precede file checks. Then plan/report name policy and
collision precede plan existence. Per row: the eighth-to-ninth bound, grammar,
whole-plan path conflict, desired existence and current existence have explicit
priority. Every predictable failure returns2 and preserves the complete file
map, including an earlier current, rollback and existing report. The row number
and plain reason identify the issue.

For changed apply jobs, current becomes desired and rollback becomes the old
current. For unchanged jobs, current and its existing rollback or absence stay
intact. Desired inputs, plan, keep and unrelated files remain intact. A report
contains one same/change row in original order plus changed/unchanged totals.
Preview prints it without writing. Apply stores the report and prints its
summary. Empty plans have a defined report and do not invent a job.

The goal assesses complete final states and predictable preflight preservation.
It does **not** assert write chronology, that an unchanged file was never opened,
atomic rename, races, temporary files, permission failures, locks, traps,
timestamps, or rollback after Stop/resource failure during ordinary writes.
The valid backup-first alternate is accepted without inventing transcript
authority. A fresh Run and current source/outcome checks determine completion.
