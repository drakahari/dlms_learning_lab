## Progression and independent assignments

`ccna-transport-conversations` follows IPv4 routed return paths and directional
access policy. Existing units and all294 scenario values remain unchanged.

- `ccna-transport-port-pairing`: match two distinct TCP report conversations to
  the server listener while keeping a UDP sensor working at the same numeric
  service port. Matching alternate TCP service ports and distinct valid client
  ports are accepted. Repairing just one conversation gives partial completion.
- `ccna-transport-return-policy`: diagnose a SYN that reaches the server but a
  SYN-ACK whose reversed port pair is filtered. Repair the real ordered ACL
  document while preserving the sensor and three forbidden probes. An explicit
  pair of destination-port permits can substitute for a supported range. A
  blanket permit, missing listener, changed endpoint or deny-all cannot pass.

The first task introduces address versus port, application listeners, source
ports, normal TCP opening and direct UDP datagrams. The second teaches actual
source/destination port placement in the existing editor's bounded IOS-style
syntax, direction, rule order and positive traffic alongside restrictions.
Essential explanations are in Introduction, with separate annotated practice
addresses and ports. A worked practice fill is explicit and never executes.
Practice settings, current results and independent drafts remain separate.

## Grading and persistence

The caller-held Definition contains separate task worlds and worked proofs.
Saved Session data holds only source identity, navigation, endpoint/config
drafts and the exact checked draft. Reports cannot be deserialized as grading
authority. Every check recomputes the real route/ACL and transport outcomes.
Editing clears checked state. Protected settings, rows, host/interface identity,
routes and separate-practice roles are bound to source. Load/save/launch/grade
guard both wrong-family directions, preserving rejected original data.

Six deterministic conversations/probes in the policy task test the two TCP
source ports, useful UDP, forbidden forward UDP, unsolicited reverse UDP and a
different reverse TCP service. Each negative restriction must be an actual ACL
denial at the named boundary, with useful traffic crossing that boundary.
This intentionally makes a blocked-everything draft insufficient evidence for
either a working service or a useful protection policy. No claim covers every
possible packet, every real TCP state or a general network security policy.
