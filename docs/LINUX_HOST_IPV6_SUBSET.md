# Linux host IPv6 extension — bounded practical subset

2026-11-06. Three registered lessons enable this extension: source catalog310labs/104units. Latest verified Fedora candidate remains307T125136Z until the new package gates pass. See HOST_IPV6_LESSONS.md for actual evidence. This is narrow partial LPIC-2 practice, not a completed issuer objective.

The existing `linux_host` engine has optional source-held IPv6 facts and matching
configuration. Missing fields default None and serialize absent; old raw worlds
and sessions keep their representations. Configuration cannot enable IPv6 without
a matching source profile. Exact authored-context/history admission remains.
New probe draft storage is optional/skipped when empty, bounded64bytes and refused
for old IPv4-only sources. The original32-byte probe field and bounds remain.

The extension reuses `ipv6::Prefix`, mask/category arithmetic, shared interface
Up/carrier facts and existing bounded publish/generation. It does not use Cisco
administrative distance for Linux routing. Up to2eligible interfaces, one manual
primary address each,4supplied scoped gateways,8known destinations and8gateway
routes. State32KiB/raw decode64KiB and existing bounded history/teaching limits
remain; no new dependencies, executable scripts or host networking route.

Supported source-enabled forms:

- `ip -6 address show [dev NAME]`
- `ip -6 address add|del ADDRESS/PREFIX dev NAME`
- `ip -6 route show`
- `ip -6 route add|replace|del PREFIX via GATEWAY dev NAME metric N`

These are literal ASCII forms only, alongside the existing IPv4 subset and shared
`ip link` operations. Metrics must be explicit positive u32 values; zero/default
normalization is deliberately unsupported. A more-specific prefix wins before
metric. A configured lower-metric gateway does not prove health or invent automatic
failover. A link-local gateway is scoped by device. Read-only output reflects the
modeled address/routes without fake kernel counters, lifetimes or RTTs.

Manual addresses are documentation/locally assigned ULA /48–/126. Subnet-router
anycast and /127–/128 **host assignments are excluded in this activity**, not
universally invalid IPv6 addresses. IPv6 has no broadcast; all-one interface bits
are accepted. Route prefixes still include/0and/128. Remove this interface's IPv6
gateway routes before deleting its primary address: this conservative planner
restriction does not claim Linux's general route/address deletion behavior.

No RA/SLAAC/DHCPv6/DAD/NDP, extra/privacy/temporary addresses, source-policy/tables/
ECMP, connected-prefix route collisions, multicast/anycast operation, arbitrary
public addressing, ping/ip-route-get, real packets, reverse-path model, AAAA/NSS
or boot persistence. Link-local target probes are unsupported; next-hop scope is
modeled. The native path test uses declared availability/onward facts only.
Existing NetworkManager lessons explicitly remain IPv4-only and refuse new IPv6
source facts rather than dropping them in an IPv4 projection.
